# 平行任务协作

用于多个独立窗口/工作树实施同一目标，以及跨任务发布、消费合同和接线。单窗口工作不加载本文。这里定义协作策略；本地状态、CAS、租约和完成门仍以[状态协议](状态协议.md)为准。

## 划分边界

按数据所有权、合同和可独立验收结果拆分，窗口数量由可分离范围决定。每个任务至少明确：

- 目标、非目标、可写路径和停止条件；其他区域可读，不能自行修改。
- 权威架构/合同的固定版本及本任务结果的版本定位方式。
- 本任务提供什么、消费什么，提供方与消费方分别是谁。
- 本地验收和涉及的真实用户/运行链路，哪位负责人完成跨模块接线。

接口提供方拥有公共合同及其实现；消费方拥有适配和调用。共享 schema、迁移序列、锁文件、生成产物及入口文档各指定唯一负责人。负责人只管理对应资源；不要求拥有所有任务上下文。生成产物按仓库现有生成入口更新，消费方不长期复制提供方源码作为另一权威。

对每条跨模块链路，明确接线负责人及允许写集，包含调用入口、错误/拒绝路径和验收环境。不要把“共享接线”“最终一起联调”当作所有者。可以由现有任务承担，或由用户另行建立有界集成任务。需要改动他人区域时提交合同/接线需求，由该区域负责人实施；重叠写入前停止相关写入者并明确交接。

## 隔离与本地状态

并发写入使用独立工作树/分支，并先核对真实路径、分支和基线。新工作树不自动包含未提交/未跟踪的架构和用户改动；必须确认批准的基线已可读取且版本正确，不用旧提交代替最新决定，也不擅自提交用户内容。

数据库、容器、端口、卷、缓存和临时目录同样需要隔离或单一负责人。Git 隔离不证明运行资源隔离；不得因测试环境可重建而重置他人依赖的共享实例。破坏性授权仅在对应项目、资源和范围内有效。

每个工作树只有自己的 `.longtask/state.json` 和状态写入者。不建立第二份全局状态、任务档案或手工同步看板；需要总览时，从各任务当前的 `route --resume-choice inspect` / `doctor --output summary`、Git 版本和验收证据提取短摘要。不要复制完整历史或把多个根的检查点拼成一个状态。

本地工作包 `dependencies` 只能引用同一检查点内的包 ID，不能用另一任务“complete”标签满足本地 DAG。外部依赖通过本任务合同和 `handoff.required_inputs` 引用可访问的版本化合同/结果，验收证据定位实际消费的版本。现有工具校验本地状态，不负责跨根锁、外部版本新鲜度或自动唤醒；这些仍需宿主/负责人核实。

## 创建、命名与派发

用户要求建立独立会话并开展领域任务时，将本节作为执行流程；只要求建议或可复制指令时交付任务文本，不自行创建。技能维护请求也不等于授权启动真实项目任务。以下使用宿主原生工具，不增加 Python 会话调度器或固定 SDK 依赖。

1. **形成可执行分工。** 从当前目标和架构确定领域、成果、写集、共享资源负责人、依赖和验收。先准备每个窗口的完整指令及可读基线，再创建；不要只有名称便启动。用户指定数量与名称时沿用，不以固定九任务模板拆所有项目。缺少会实质改变合同/范围的信息才提问，常规名称和拆分可自主决定。
2. **确认目标与复用。** 发现当前可用的原生会话能力；Codex 优先查找 `list_projects`、`list_threads`，需要了解候选窗口时用 `read_thread`。以返回的项目 ID、会话 ID、实际标题和领域范围匹配；不凭名称就复用，不编造 ID。适合的原窗口继续使用；只有用户已要求创建/续接相应任务时才执行对应动作。
3. **确定名称与环境。** 使用短且可区分的“项目 · 领域 · 成果”名称，编号仅辅助排序；名称与指令中的责任一致。按工具支持的字段提供 `title`，需要修正既有名称时用 `set_thread_title` 并采用返回的实际标题。项目任务先用真实 `projectId`；工作树模式和起始状态严格按用户请求及工具合同选择，不擅自指定分支/ref、模型或推理等级。并发修改必须有隔离工作树；若当前授权/宿主只能提供共享目录，先说明缺口并提供顺序或只读分工，不能启动重叠写入。
4. **创建或续接。** 新任务用 `create_thread` 携带完整初始指令；当前请求仅拆分/执行领域任务时使用 local 项目类型，不擅自转成云任务。复用窗口时，在用户授权下用 `send_message_to_thread` 发送有界续接指令。独立用户窗口用原生会话工具，当前会话的内部审查/辅助才用子智能体。发消息授权遵循下节规则。
5. **核对派发结果。** 记录工具返回的真实会话 ID、宿主、标题及已就绪/初始化中/失败状态；初始化中的 `clientThreadId` 不能冒充可读写的 `threadId`。创建结果不确定时，先查会话列表或操作状态，不能直接重试制造重复任务。已确认失败只重试该任务，保留已成功任务。需要更正指令时先核对收件人领域，不群发整段主会话。
6. **交付窗口映射。** 返回“领域 → 实际名称/ID → 边界 → 依赖/接线负责人 → 当前状态”，并按宿主要求展示已创建会话入口。创建成功不等于执行完成；要求跟进时用紧凑的 `wait_threads` 快照/游标，按工具上限分组，初始化未就绪的任务使用其操作状态入口。无变化不反复读取历史。仅创建/派发的请求在核实结果后交付，不强制保留常驻总控。

派发记录保留在宿主会话结果及当前恢复输入中；不另建长期任务登记库。任务窗口拥有自己的实施上下文。若已创建部分窗口后中断，恢复时先核对已存在的真实任务及边界，再创建尚缺窗口，不从数量推断成功。

每个窗口的初始指令可以直接按下列字段生成；使用真实路径/版本/负责人填充，未确定的外部输入明确标注缺口，不留下看似可执行的占位值：

```text
任务名称：项目 · 领域 · 预期成果
目标与非目标：本区域应交付的结果；不承担的其他区域
工作区与基线：真实工作树路径或工具创建结果；权威架构与固定版本
可写范围：本区域路径；共享资源及其唯一负责人
提供/消费合同：权威定位、依赖版本、对应区域；依赖到达后的下一动作
接线责任：本任务负责的实际链路及其他负责人
验收与停止条件：适用检查、预期证据、越界/缺失/失败时如何处理
完成与交接：区域/集成/系统的声明边界；本地检查点和必要文档的去向
```

工具不提供会话创建或无法解析项目时，保留完整且命名明确的可复制指令和具体能力缺口，不假称窗口已建立。工具支持创建但用户未要求时，也不自动调用。

## 发布、消费与续接

提供方尽早交付最小可用合同和代表性 fixture/调用入口，注明固定提交或可核验内容摘要、已验证范围和限制；不必等整个区域收尾才允许联调。只有示例而无实现时明确标注，不能称为接口已交付。

消费方收到材料后，先核对实际产物、版本、合同和本地授权，再更新所需输入、依赖判断及适用验收；能够推进就继续适配与检查，只回复“收到”不代表消费完成。缺失材料、版本不符或工具不可用时，报告具体缺口并推进独立工作。消息不是验收证据，也不授予新的写入或副作用权限。

等待外部材料时，在既有 `handoff` 中写明所缺输入、到达后的下一动作及成功/失败出口。已登记的正式 blocker 按状态协议关闭，不能直接删除或凭消息宣布解除；内容/合同漂移时先协调检查点，需要时 supersede 后重建包，不扩大已启动包的写集或重写基线。

提供方更新合同或修复时只通知受影响消费者；消费方重验受影响链路，不能将旧结果绑定到新版本。没有自动续跑能力时，发布消息不会自行唤醒接收窗口；需要实际续接动作。只有用户明确授权向目标任务发送消息时才使用宿主发消息工具，否则将可复制的交接文本交给用户；不得收到一个任务请求就自动转发或回信。

同一区域的延续优先使用原窗口；上下文污染、独立审查或独立集成时使用新窗口。新窗口只带当前目标、边界、有效检查点、固定版本及必要证据，不带整段对话。创建用户可见的新任务遵循用户授权，独立审查不接收作者的预期结论。

## 最小交接

消息用于定位产物和指定下一动作，详细合同保留在所属模块。按实际缺口填写，无须每次状态更新重复模板：

```text
交接类型：合同可消费 / 修复需重验 / 请求接线
提供方 → 消费方：区域或任务标识
权威输入：可访问路径 + 固定提交/摘要；不要只写分支名或“最新”
已验证与限制：实际命令/结果或证据入口；模拟、真实及未运行分开
接收方下一动作：具体适配、检查或仍缺材料
接线负责人及完成条件：谁负责哪条链路，如何判定通过
```

消息较长时将合同留在权威文档，仅发送版本、定位和动作。显示截断与实际传输缺失应通过原始内容/产物核对，不因界面省略而重复发送整份上下文。

## 验收收敛

区分三个结果：区域实现通过、消费者集成通过、系统验收通过；各自绑定实际版本与环境。提供方本地完成不能替代消费方适配，更不能证明系统完成。

依赖可消费时就跑最小真实链路，尽早发现读/写接口、授权上下文和运行接线的缺口。最终集成冻结各区域结果及依赖版本，由指定负责人在组合版本验证适用用户旅程、拒绝路径和恢复行为；本地模拟、fixture 或跳过的外部服务检查不得充当真实集成通过。

合并前核对合同/来源版本与重复改动，按所属权威收敛；相同路径的差异不自动等于冲突，也不能只按“最后修改”选取。集成改动使受影响证据过期；重验范围由变化与风险决定。局部任务按本地完成门收尾，剩余真实集成缺口在对应模块限制中保持可见，不为所有窗口凑齐完成标签而隐藏。
