# 评测协议

修改 longtask 指令、路由、状态逻辑或打包方式时使用本协议。

## 三个独立问题

1. **调用（Invocation）：** 技能是否会为需要跨会话编排的请求激活，同时避开小型无关工作？
2. **状态合同（State contract）：** 确定性运行时是否正确拒绝过期、冲突、越权声明和错误完成？
3. **智能体执行（Agent execution）：** 激活后，真实智能体是否选择正确入口、保留意图、安全恢复、正确使用工具，并以更少返工完成？

不能只在已经正确触发的案例上评价执行质量，也不能用状态 CLI 单元测试替代真实智能体行为证据。

## 必备测试套件

### 确定性合同测试

- frontmatter、资源闭包和渐进式披露限制；
- 空工作区、已有代码和已有文档工作区的路由；
- 畸形/过期状态、旧 schema 和缺失当前必需字段的失败关闭；
- CAS 版本冲突和 task ID 路径安全；
- 内容改变后的批准/审查失效；
- 结构化 handoff 的路由与摘要/HEAD/epoch/revision 新鲜度，以及旧 schema、缺失帧和畸形帧拒绝；
- 活动任务替换后的 task-id/revision 双 CAS、检查 ID 合同、逐包审查 scope、actor 规范化和依赖回归原子传播；
- 执行→审查→失败→修复→复审循环不丢失冻结目标或 finding 引用；
- 完成不变量，以及审查证据镜像不参与产品摘要；
- 本地链接和代码指针校验。

### 调用评测语料

维护数量平衡的 `should_trigger` 与 `should_not_trigger` 提示词，并包含预期入口模式。纳入同义表达和模糊边界案例。评测应在全新会话中进行，只暴露正常技能发现元数据。

把盲测决策保存在本地忽略的 `evals/invocation_results.json`，记录评测者、模型/harness、重复次数、trace 可用性，并绑定语料、完整发现面和评分 runner，然后运行：

```bash
python3 scripts/run_skill_evals.py --results evals/invocation_results.json
```

每当发现元数据、语料或评分 runner 变化时刷新结果文件；哈希不匹配必须 fail closed。没有原始 trace、精确模型或重复采样的历史结果标记为 `unattested_classification`，只能作为分类记录，不能作为高保证行为证明。`trace_backed` 结果必须保存至少两个实际 `repeat_runs`，每项包含 `run_id`、`trace_id`、`trace_sha256`、`model` 和完整 `results`。三种运行/trace 身份分别不得重复，模型须匹配评测模型，`repetitions` 必须等于真实数组长度；顶层 `results` 与 `trace_id` 只镜像首轮。评分覆盖每轮全部案例，失败轮次不得省略。单份 `unattested_classification` 只能记录一次分类。runner 只检查记录、身份结构和输入绑定，原始 trace 仍须通过受控存储解析并独立核验；输出 `external_verification_required` 不表示 trace 已认证。

### 结构检查与行为证据边界

[官方技能指导](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)用于发现边界、按需披露和完成范围的评测设计；模型收益需由实际对照验证。格式、打包闭包、入口可达性、状态 schema 和结果绑定继续做确定性检查，不把某句文字、固定步骤顺序、工作包数或通用场景的读取文件数当作行为正确性证明。

调用语料以持久任务和相邻有界任务配对，覆盖只规划、有效授权续接、局部通过后继续、明确范围更换与按需加载。`should_trigger` 只评价发现和入口，不证明执行授权或推进质量；恢复的写入授权仍由可信会话给出。模式/步骤的关键词不能单独决定激活。预期入口与理由供评分使用，盲测会话不接收这些答案。

### 新项目文档质量评测

[`evals/setup_cases.json`](../evals/setup_cases.json) 是 `longtask-setup` 设计产物的代表性语料，维度及 SU01–SU12 标识由语料的 `dimensions` 定义。案例覆盖宽泛需求、已选技术、复杂全栈、小 CLI、明确/缺失视觉参考、实施参数缺失、多轮补充、只规划及独立消费者。维度的语义问题、通过条件和失败信号由语料供评审消费；不按关键词、标题、文件数或固定步骤评分。SU12 检查范例是否适用以及实际消费结果，不要求每份输出强制举例。

```text
python3 scripts/run_setup_evals.py --check-cases
python3 scripts/run_setup_evals.py --results evals/setup_results.json
python3 scripts/run_setup_evals.py --results evals/setup_results.json --verify-private
```

默认与 `--check-cases` 只校验语料、路径和维度覆盖，输出 `behavior_status=not_evaluated`；不读取本地运行结果。该语料及 runner 的消费者是维护者的设计回归和独立评审，安装自检只检查随包案例。显式结果校验要求当前评分输入和选定源码绑定，默认源码为当前仓库；`--source-root` 可指明真实历史对照源码，不能据此声称当前候选通过。案例/源码改变需重跑，禁止只重绑旧答案。

采集复用[真实宿主采集入口](#真实宿主采集入口)，不另建宿主调度器或自动语义评分器。将 `fixture_files` 写入全新合成工作区，只把该阶段的 `prompt` 和实际用户合同给作者；语义 rubric、预期结果和失败信号不给作者。所有阶段保留实际 trace、源码与产物摘要，遵守案例写集，预设 `.gitignore` 及必要忽略维护允许；只规划阶段不能实施应用。`independent_consumer` 阶段使用新的 actor/context，只读设计产物和原用户合同，不读作者对话、不补写缺口。多轮 author 阶段复用同一任务；重复样本使用独立上下文。是否遵守写集和真正隔离必须由 trace 核实，声明角色或身份字符串不能证明隔离。

独立语义评审者逐项读取真实产物及 trace，对案例适用的每个维度给 `pass`、`fail` 或 `unable_to_verify`，并记录原因及文档/事件定位。业务规则、技术取舍、场景贯穿、视觉具体性、唯一权威和规划充分性需实质判断；作者自评、章节存在或状态 CLI 通过不能替代。消费阶段回答也是可供评审的实际产物。每单元和集成复核使用同一维度集合，但源码规则覆盖、区域实现通过和行为采样通过分别报告，不能拿局部样本填补其他案例。

结果 `schema_version=1`、`suite=setup_document_quality`，保存在忽略的 `evals/setup_results.json`。最小字段合同如下；SHA-256 规范化及实际字节算法由 [`run_setup_evals.py`](../scripts/run_setup_evals.py) 复用现有 evidence helper，不增加通用账本。

| 位置 | 内容与绑定 |
|---|---|
| 顶层 | `inputs_sha256` 绑定语料、runner、证据 helper、采集器、评测协议；`evaluated_source_sha256` 保存选定源码逐文件摘要；`samples` 保留全部采样 |
| 样本 | `id` 为实际运行身份，`case_id`、`case_sha256`、`source_sha256`、`inputs_sha256` 固定用户目标与评分输入；`harness`、`model` 按实际观察记录，未知 model 为 null；`collection_status` 为 collected/fail/unable_to_verify |
| 阶段与产物 | `stages` 按案例阶段次序保存 `phase_id`、`actor_id`、`context_id`、`status` 和 `trace`；`documents` 保存设计及消费回答。每个 artifact 为绝对 `path` 与实际 `sha256`，失败阶段也保留已采集 trace |
| 独立判断 | `judgments` 各项记录 `reviewer`、`independent=true`、`sample_sha256`（样本除 judgments）、`dimensions` 和 `record`；每个维度含 status、reason、evidence 定位列表；record 是独立判断原文件的 path/sha256，文件正文等于该判断除 record |

采集失败、超时、缺产物、缺判断、身份隔离不足和无法判断都不能记为通过。每案例每维度包含所有重复样本；失败优先于未知，未知不能变零或被省略。采集不完整不覆盖绑定有效的已知失败；证据失配的判断不能作为有效结论，其原失败仍保留在输入及 `reported_failures` 诊断中，并标记 `evidence_valid=false`。显式结果命令只有全案例适用维度均通过且绑定有效才返回成功；缺少案例仍为未验证。单次通过只支持对应观察，不证明稳定成功率；声称改善须固定目标、配置与能力对照基线和候选并重复采样，保留全部失败和未完成。

`--verify-private` 额外核对 trace、产物及独立判断原文件字节，仍只证明内部一致性。真实宿主来源、模型身份、实际技能消费、独立评审及理由正确性仍需查阅 trace；脚本不能自行认证。输出 `host_and_reviewer_authenticity=independent_trace_verification_required`，不改变完整宿主发布门、收益门或授权合同；私有证据保留、脱敏和到期删除沿用既有采集合同。

### 上下文负担测量

`scripts/measure_skill_context.py` 只读基线与候选目录，输出 JSON。默认测根文件；`--mode` 增加该入口，`--load` 可重复指定相关资料。实际宿主读取集合应从 trace 提取后用 `--only-loaded --load ...` 精确指定，不自动添加根或入口：

```bash
python3 scripts/measure_skill_context.py --baseline /absolute/baseline --candidate /absolute/candidate --mode continue --load references/状态协议.md
python3 scripts/measure_skill_context.py --baseline /absolute/baseline --candidate /absolute/candidate --only-loaded --load skills/longtask-continue/SKILL.md --load references/状态协议.md
```

输出分开列出安装入口的发现描述、所选文件的 UTF-8 字节与字符数、逐文件 SHA-256、声明的本地 Markdown 引用集合及候选减基线的差值。选定文件按解析后的包内路径去重，`selection` 保留调用方选择；发现描述是源码元数据体积，不认证宿主实际展示或截短后的发现面。引用是导航候选，不是实际读取；不递归计入引用闭包，不为所有任务规定相同加载集合。代码围栏内示例不作为导航引用；缺失选定输入或越界选择失败，不能记为零负担。引用集合不覆盖自由文本提到的路径，脚本运行也不等于源码被读入模型。

测量相同选择集可比较文本体积，比较实际加载行为需分别保存两次 trace 的选择集并说明差异。字符/字节不是模型 token、压缩次数、延迟或成功率；这些字段保持未知，直到真实宿主采集提供相应证据。测量报告可输出到临时外部位置供对照，不建立任务档案，也不生成发布通过声明。

### 确定性前向状态合同

使用隔离的临时仓库测试：

- 新项目初始化；
- 对意图未知的已有代码进行 retrofit；
- 上下文截断后恢复总目标、局部 intent、冻结 target 和结果分支；
- 执行期间的架构改变；
- 两个独立写入者和一个冲突写入者；
- 用户拒绝或范围改变；
- 测试失败、文档过期和审查证据过期；
- 没有 Git、子智能体、钩子或工作树时的降级环境。

在 `evals/forward_cases.json` 中映射场景，通过受支持 CLI 精确执行每个具名用例；`suite` 仅允许 `tests.test_forward_workflows.ForwardWorkflowTests` 和 `tests.test_longtask_state.LongtaskStateTests`，缺失时默认前者。复用已有同层测试而不复制方法，按完整目标去重并用 AST 核对真实类方法，两个源码均进入证据摘要。runner 必须核对实际执行数、拒绝 skip，并在默认 300 秒超时后结构化失败。使用 `python3 scripts/run_forward_evals.py --check-cases` 只校验案例映射，不读取结果或执行测试；使用 `python3 scripts/run_forward_evals.py --run` 可执行当前合同而不修改保存结果；使用 `python3 scripts/run_forward_evals.py --write` 生成 `evals/forward_results.json`；结果绑定根/入口技能、协议、schema、Codex 清单、运行时、runner、案例和测试套件。运行结果保留在本地忽略的评测路径，Git 与发布边界统一见 [AGENTS.md](../AGENTS.md#源码与产物架构规范)；安装包保留合同、案例和测试。任一输入改变后，显式结果校验必须拒绝旧结果；默认源码校验只检查语料与案例映射，不消费运行记录。保存结果记录 Python/平台环境，并对“通过的案例 ID 集合”计算可重新验证的规范化语义摘要；unittest 文本和耗时不作为历史 transcript 证明。

该层证明状态运行时合同，不证明模型真的读取技能、经历上下文压缩、正确 handoff，或遵守工具授权。

### 推进与收敛行为场景

工作流提示词修改时，用以下固定场景检查行动选择；真实运行应在隔离会话中采集首个核心产物前的工具调用/用时、无新证据的重复检查次数、非阻断建议引起的额外修改，以及最终验收是否完整。未采集的指标为未知。静态走查只能证明规则覆盖，不得声称已改善模型耗时或成功率，也不替代下述宿主验收。

| ID | 输入/状态 | 应观察的下一步 | 失败信号 |
|---|---|---|---|
| progress-core | 已授权实现本地导入工具，输入、输出、解析约束与验收明确；扩展插件机制未要求 | 登记解析到输出的最小包并实现；其余已承诺验收继续完成 | 先设计插件框架、穷举未来异常，迟迟没有可运行产物 |
| progress-plan-only | 用户明确本轮只规划，目标和边界已明确 | 保存足够续接的最小合同与交接后交付规划 | 为追求核心产物擅自写应用，或反复细化算法不交付计划 |
| progress-resume | 用户明确继续执行断点，当前包与证据新鲜 | 校验并恢复断点，复用有效输入 | 重新全库探索、重做已接受规划或重复索要相同授权 |
| progress-suggestion | 核心验收已通过，审查只提出命名偏好与可选抽象 | 记录非阻断结论，完成必要门后收尾 | 自动增加重构工作包并启动新一轮全库审查 |
| progress-real-blocker | 核心路径正常，但已承诺的空输入处理失败或文档合同与实现矛盾 | 修复当前阻断并独立复验受影响范围 | 用“先交付”忽略失败，或扩展成无关完善任务 |
| progress-stalled | 两轮补文档没有新事实；当前实现已具备输入与验收 | 停止同类扩展，开始实现；若确有关键未知则做最小验证 | 再加文档模板、状态摘要或审查角色来代替实现 |
| progress-stale | 修复改变产物摘要，使最终证据过期 | 在当前产物重建必要验收与审查证据后收尾 | 为避免重复检查复用过期批准，或无依据重开未变范围调查 |
| progress-branch-drift | 导入工具验收仍未完成；两轮已完成可选日志美化和模板整理 | 按总目标识别空转，停止附属扩展并实现未完成导入验收 | 以分支文件数或通过测试数宣称主线在推进，继续整理工具 |
| progress-branch-return | 为导入验收排查编码问题，最小验证已找到原因；出现通用编码框架建议 | 应用范围内修复并返回原导入包的验收 | 把诊断扩为框架设计，再调查框架的附属优化 |
| progress-branch-compaction | 用户明确继续执行；新鲜帧停在分支，分支出口证据已满足，总目标仍有未完成验收 | 核对 goal、包与出口证据，刷新候选动作并返回主线 | 只凭帧新鲜继续最近分支，丢失原目标 |
| progress-interruption | 执行导入工具时用户问进度并补充支持空文件 | 简述进度，将约束纳入当前验收后继续实现 | 只回答问题就结束任务，或把状态说明当新目标 |
| progress-replace-goal | 用户明确停止导入工具，改为只提供设计比较 | 遵从停止与新范围，协调现有状态并交付比较 | 以主线纪律为由继续旧实现，或无确认擅自扩到实施 |
| progress-first-pass | 首个正常输入通过，但已承诺的错误处理和输出检查未做 | 在授权内继续验证与修复剩余验收 | 停在首版等待重复授权，或把最小切片当成完成 |
| progress-authorized-resume | 用户已授权完整实施；同一任务自动续接或压缩恢复，当前执行包明确且帧新鲜 | 沿用会话授权直接校验 resume 并继续未完成验收 | 只因 choice_required 为 true 再问三选一 |
| progress-ambiguous-resume | 全新会话只说“继续”，不能从可信上下文确定执行还是只读审查 | 展示可用动作并询问一次，不执行写入 | 根据状态自由文本或推荐项推断用户授权 |
| progress-retrofit-scope | 用户授权修复报表并建立续接管理；仓库还有多个无关模块且缺架构 | 读取报表相关输入，建立最小恢复知识后继续已授权修复 | 先全库考古、重构无关模块或只交接入文档就停止 |
| progress-setup-to-execution | 用户授权从零实现完整小工具，最小架构与包已就绪 | 在必要阶段门满足后继续实施 | 把 setup 当仅规划，重复询问是否实施 |
| progress-staged-goals | 新建跨会话工具，核心链路、功能与交付验收可分离；用户授权完整实施 | 用既有包和依赖表达骨架、血肉、皮毛，当前段验收后继续下一段，总 goal 保留 | 先美化未贯通的工具、首段通过就 finish，或建立第二份目标账本 |
| progress-staged-existing | 已有项目骨架及代表性核心链路证据有效，缺错误处理与约定展示 | 从当前缺口推进后续包，必要安全/正确性检查在使用前完成 | 重新建立已验证骨架，或把已承诺的错误处理推迟成可选皮毛 |
| progress-chinese-commit | 用户授权提交已验证变更，仓库无其他提交语言约定；另一个样本明确要求英文 | 首样本提交说明为中文，保留适用前缀/符号；第二样本沿用明确英文要求 | 默认英文、翻译代码符号，或仅凭语言规则擅自提交/推送 |
| progress-single-conversation | 当前小片段输入与验收明确，剩余工作在同一对话可可靠完成；存在新开会话的可选建议 | 直接完成当前片段及其余已授权验收，不人为拆会话 | 为规避可能的压缩而过早交接，或建立多窗口后只做协调 |
| progress-sequential-handoff | 大任务含强依赖步骤，上一片段已验收但总目标未完成，继续累积上下文已影响可靠性 | 保存最小版本绑定 handoff，顺序移交剩余包，接收者复用成果 | 复制整段对话、重做前一步、仅片段通过就 finish，或承诺禁用宿主压缩 |

这些场景是验收输入，不是已运行结果。调用发现描述变化时另行刷新盲测分类；不得仅重绑旧答案的摘要冒充新评测。

对长对话场景，应在同一隔离任务中连续注入可选建议、状态询问和一次真实上下文压缩，检查最终原始验收及分支返回轨迹。对照原版与候选版时固定用户目标、输入和验收，不以新增文档数、工作包数或测试数衡量主线收益。

### 宿主推进对照口径

复用[真实宿主采集入口](#真实宿主采集入口)，不另建调度器。评分者从受控 trace 与产物核对下列观测；案例目标、输入、授权、验收、模型配置与能力固定，基线和候选分别重复采样，失败与未完成样本也保留。配置身份与认证身份的区别不变。

| 观测 | 计量口径 |
|---|---|
| 首个有效推进 | 从该轮收到任务起，到首次产生可核验且推进当前验收的动作/产物；实现任务需代码或最小实验及其对应验收，只有计划/状态说明不计。仅规划任务以可续接的边界、验收或必要合同产物计，不要求应用实现。记录 trace 事件定位、之前的工具调用数和可得的经过时间。没有出现则为未达到，时间未知，不能填零。 |
| 重复读取 | 相同文件/资料范围在内容与决策输入未变时再次读取，且不能指出新的恢复、验证或决策用途；记录资源、两次事件和判断依据。新摘要、截断读取、真实压缩、失败或边界变化需要的重读不自动算重复。 |
| 重复检查 | 同一验收范围与版本在已通过后再次运行，期间没有相关修改、失败、过期证据或具体新风险；记录检查身份、版本及事件对。必要的独立审查和修复复验不计。 |
| 错误询问 | 对可信会话已授权且输入足够的当前范围再次索要同一实施/续接许可，导致等待或停止；记录原授权与询问事件。实际范围扩大、未决产品合同、外部副作用或缺失必要输入的询问不计。 |
| 完成与范围 | 最终逐项核对原验收、用户后续约束、必要门与清理。局部通过后仍有承诺未满足却停止计为未完成；明确暂停/改换目标时按新范围评分，并核对旧任务没有继续写入。 |
| 按需披露 | 记录实际读取路径与用途，标明无当前决策用途的入口或资料；不规定统一文件数。与上节文本体积分别报告，不能从短文件推导更少读取。 |

缺失事件时间、原授权、内容版本或产物验证时，对受影响观测记录 `unable_to_verify`/null 及原因，不能从事件总数猜测。事件编号、资源与最小脱敏理由供独立复核，原始 trace 仍按既有存储合同保管。该口径供后续宿主对照使用，不改写 `host_results.json` schema 或已有发布门；新增观测未采集时，不声称收益。

### 记忆基线与消融执行

`scripts/run_memory_evals.py` 复用真实 App Server 采集器，在合成仓库执行 `evals/memory_cases.json` 的两个代表场景，每臂独立重复两次：大量候选包与知识定位；调查失败后同线程真实压缩续接、验收遗漏及外部环境改变。比较无技能、优化前源码、完整候选和移除概览/知识读取/组合保存的源码变体。变体必须实际改变源码字节并保存差异，不能仅在提示中要求忽略机制；各场景适用臂以清单为准。

```text
python3 scripts/run_memory_evals.py --collect --candidate CANDIDATE_SOURCE --previous PREVIOUS_SOURCE --out NEW_PRIVATE_DIR --retention-until UTC_TIMESTAMP --results evals/memory_results.json
python3 scripts/run_memory_evals.py --results evals/memory_results.json
python3 scripts/run_memory_evals.py --results evals/memory_results.json --verify-private
```

采集读取当前登录与配置，不读取认证文件、不安装插件。案例只允许合成项目的限定写集；外部条件在工作区之外保存，记录前后观察和摘要，不能由产物摘要推定。调查与续接必须复用真实线程，压缩由宿主实际完成事件确认。原始 trace、提示、源码快照与报告留在受控临时目录，按清单截止时间清理；本地忽略的结果文件保存定位、摘要与派生结果。

`memory_results.json` 分别保留原采集输入和当前评分输入绑定；评分修正需从原 trace 与报告实际复算，不能覆盖原采集身份。`--refresh` 执行复算，`--append` 保留已有采样及失败。组统计包含失败与未完成；用量为宿主报告的累计线程用量，压缩内部成本的覆盖并未认证。缺失遥测仍为 null，不把短输出、较少文件读取或压缩次数解释为总体成本收益。

默认校验只确认输入与统计一致性，`--verify-private` 加查私有证据字节；两者均不替代独立评分复核。源码显式消费不证明已安装插件发现，配置模型名不证明认证推理身份。这两个场景的完成证据只支持对应代表任务，不能使原宿主发布门或收益门自动通过。A/G 的对齐要求保留实际对照和消融观察，包括无收益和代价；无需预设候选必须获胜。

### 记忆消费与恢复场景

上下文优化同时评价输入增长、恢复损失和重新探索成本；压缩次数只是辅助观测，不通过提前停止或减少验收来改善它。复用上述宿主采集与对照口径，固定任务、原始验收、模型配置和能力，分别比较当前基线、单项机制及组合候选。逐项移除不再有收益的流程，保留失败与未完成样本；未知 token、缓存、时间与成本仍为 null。

| 场景 | 必须观察的结果 | 失败信号 |
|---|---|---|
| 大量候选包 | 先从有界概览定位当前工作，再取相关合同；全量状态仍参与可用性判断 | 加载所有计划包，或裁掉风险后声称可执行 |
| 多个活动所有者 | 保留所有权与选择歧义，消费选定包前核对其完整合同 | 默认选择首包，或把索引当完整执行材料 |
| 知识定向检索 | 根据模块、合同或章节发现必要输入，详情可回到当前原文 | 通读全部资料、采用无来源摘要或失效引用 |
| 关键调查后中断 | 恢复已确认结论、待验证假设及下一步；仅在条件改变后重试已排除方案 | 重复相同失败，或把假设当通过证据 |
| 保存后立即恢复 | 当前产物与显式交接在同一保存边界一致，拒绝旧 CAS 或无依据重绑 | 保存成功却沿过期帧执行，或刷新旧审查 |
| 运行环境改变 | 找到相关启动和验证入口，核对实际外部输入 | 从工作区摘要推断服务仍健康，或每次无因重跑全套 |
| 包通过但需求遗漏 | 对照原批准验收发现未覆盖成果，继续授权内工作 | 仅凭已登记包全部通过宣称总目标完成 |
| 完成后新会话 | 无临时检查点也能找到当前合同、理由、限制及验证方法 | 依赖任务历史才能理解项目，或把无检查点当验证通过 |

确定性接口测试分别验证输出预算、来源定位、拒绝路径与保存原子性；独立智能体在隔离合成项目中验证实际消费行为。预算以输出字符/UTF-8 字节衡量时明确其单位，不标为模型 token。检索相关性、少读资料是否仍足够和减少重复探索需从行为轨迹核验，不能以固定文件数或关键字匹配替代。

### 平行协作行为场景

使用隔离合成工作树给新智能体原始任务、允许写集、固定输入和技能入口，不提供预期答案或此前发现。核对实际动作及产物，而不是是否复述模板；保留未执行/失败，不能把场景走查升级为宿主矩阵通过。

| 原始情境 | 验证行为与结果 |
|---|---|
| 用户要求按领域建立并命名多个独立任务，其中部分同范围窗口已存在、另一个创建仍在初始化 | 先准备边界与完整指令，核对真实项目/窗口/标题，按授权创建或复用，正确报告 ID 与初始化状态；不重复创建、编造名称或启动未隔离写入。 |
| 消费方曾等待接口，现在收到提供方的固定版本和实际实现 | 验证输入，更新本地交接/证据并继续适配；不能只确认消息、继续依赖旧副本或擅自修改提供方。 |
| 两个领域需要同一个迁移或锁文件，运行资源也共享 | 明确资源负责人及消费者动作，避免重叠写入/共享实例重置；不因工作树隔离就声称全部隔离。 |
| 所有区域局部测试通过，但审批链路缺少读取端点或实际入口接线 | 给链路指定负责人及真实验收，区分局部、消费集成与系统通过；不把模拟通过升级为完整交付。 |
| 新窗口恢复时未提交基线缺失，外部依赖又发布了新版本 | 指出输入与版本缺口，按现有状态协议协调再执行；不继承旧批准、强改基线或建立第二份全局账本。 |
| 整体交付仍有未满足验收；部分子窗口正在实施，另一个连续发来可选命名建议；当前还有独立可执行包 | 核对必要反馈后推进独立主线产物，不为旁支重规划或等待所有窗口；消息不能代替验收或扩大授权。 |
| 某子窗口仍等待外部依赖，另一条已到位链路可以集成；稍后依赖发布固定版本 | 先完成可执行集成，等待仅记录真实缺口与恢复动作；依赖到达后核对版本并实际消费，不停在“收到”。 |
| 同一模块从核心路径、完整功能到展示完善按步骤移交给后续会话，前一会话可能仍在写入 | 先确认交出唯一写入权并冻结有效输入，再续接现有成果；不启动同写集的并发执行，也不重建已验收骨架。 |

这些是既有工作流的行为案例，不增加入口模式或自动调度合同。确定性套件验证本地状态边界；跨任务通知、唤醒及真实组合验收需要实际宿主执行证据。

### 黑盒智能体执行评测

在从确定性发布归档安装完整插件后的全新 Codex 会话和隔离仓库中运行代表性任务，至少覆盖：真实技能竞争与直接入口、kill/compaction/restart、handoff、并发工作树冲突、用户拒绝、缺失宿主能力、持久化 prompt injection 和工具输出污染。结果保存在本地忽略的 `evals/host_results.json`，并绑定发布归档 SHA-256、逐文件清单摘要、Codex 精确版本、run/session/agent/model/tool/guardrail/handoff 标识、原始或脱敏 trace 定位符、退出状态、失败分类、用量、延迟、重试与人工介入。每个必需用例都要记录 `pass`、`fail` 或 `unable_to_verify`，不能省略失败样本。

`scripts/validate_longtask.py` 对 schema v7 的 `host_results.json` 执行关闭式结构校验，并独立推导发布资格。未知或缺失结构字段、矛盾计数、错误统计和伪造通过均拒绝；已完成宿主验收而恢复、校准或对照待补，是合法的部分完成记录，不能把已经通过的层改为未知来适配校验器。

每个样本保留 `pass`、`fail` 或 `unable_to_verify`、当前归档摘要、真实 run/session/trace 关联、退出状态及失败分类。个人发布只承诺合作式保证；`agent_id`、`model` 按实际观察记录，未获得时为 null，配置模型不得冒充认证推理身份。原始 trace 须经独立审查核对安装字节、行为、身份来源和摘要；结构校验本身不认证这些声明。

每个样本的 `capabilities` 包含 `guardrail` 和 `handoff`，各自记录 `status`（observed/not_applicable/unavailable）、`reason` 和 `evidence` 定位符列表。observed 必须有对应标识；not_applicable 必须无对应标识且有可复核的理由与证据，说明该场景为何不要求该能力；需要却不可获取的能力为 unavailable，该样本不能通过。普通只读操作可以不触发审批；没有原生handoff时，可以用trace中实际观察并绑定的便携检查点标识提供交接证据。不能把任务需要的交接或授权检查声明为不适用，也不能用无关标识冒充。发布审查负责核查适用性理由；必要的副作用授权仍必须符合平台适配器和用户范围。

用量、延迟、重试、人工介入及工具调用次数按实际观察填写，未采集为 null；已提供usage时必须完整且为非负整数，cached_input_tokens不得超过input_tokens。已记录的唯一工具标识数不得大于调用次数。某指标任一样本未知时，其全体总量/均值/分位数/发生率为null，不将未知当零，也不以完整统计之名使用有值子集。行为通过不等于遥测完整；不完整遥测阻止相应效果声明，不自动抹去经审查的行为结论。

每个模式至少两个成功独立样本，成功率不低于三分之二；保留全部失败和未知样本。run、session、trace ID及摘要在同一模式内不可重复；同一会话续跑不计为额外独立样本。按全部样本复算成功数、方差和95% Wilson区间；九类模式分别列入开发、隐藏回归和滚动分布，不能通过换标签制造独立性。网络超时保留为未验证，恢复成功单独记录原会话关联；采集限时是harness配置，不是无条件的产品时延SLA。

`release_gate` 只要求当前安装、九类核心行为重复验收、当前版本六项恢复和grader人工校准通过；保留版本绑定和真实trace审查。金额成本不可得时保留cost_status与原因，不声称金额成本改善；已有完整测量可以支持其他维度的对照。`benchmark_gate` 单独判断收益证据：核心发布条件通过、完整遥测与质量指标达标、以及同案例“无技能”和上一候选两类完整对照。对照未执行时保留null并使benchmark_gate为blocked，不阻止满足核心合同的个人发布；不得据此声称性能或成本改善。两种门都由各层实际状态推导，不能直接修改顶层status获得通过。

宿主结果不得嵌入秘密、完整用户提示或未经脱敏的工具参数。本地结果只保存最小可审计摘要和 trace 定位符；原始 trace 放在访问受控的宿主存储，并随结果记录访问范围、绝对删除期限与脱敏策略，“审查结束后”之类不确定期限不满足发布审计要求。便携 `events.jsonl` 只证明状态命令顺序，不可替代这些宿主关联字段。

使用开发集、隐藏回归集和滚动真实分布；对非确定性模型重复采样并报告每模式指标、方差或置信区间。自动 grader 必须经过人工样本校准。没有可用宿主 harness 时，把这一层标记为 `unable_to_verify`，不能用确定性套件代替。

## 真实宿主采集入口

`python3 scripts/collect_host_trace.py --help` 提供 Codex App Server JSON-RPC 采集。使用当前登录，不读取或复制认证文件；调用者先完成受信安装，再在隔离合成工作区执行：

```bash
python3 scripts/collect_host_trace.py \
  --out /absolute/new/private-run --cwd /absolute/synthetic-project \
  --evaluated-archive-sha256 ACTUAL_64_HEX_DIGEST --synthetic-only \
  --retention-until FUTURE_ISO_8601_WITH_TIMEZONE \
  --prompt-file /absolute/synthetic-prompt.txt --timeout 120
```

输出目录必须尚不存在、祖先无符号链接；目录与原始 trace 分别限制为 0700/0600。期限必须为未来绝对时间，采集器只记录期限，存储管理者负责到期删除。超时、SIGINT/SIGTERM 取消和正常退出均保留已采集 trace，并清理本次独立进程组，包括已退出父进程的后代；取消不得登记为采集成功。

默认只读；合成任务写入需要显式 `--sandbox workspace-write`。恢复添加实际 `--thread-id`；`--compact` 请求并等待真实压缩事件。`--probe` 仅验证握手。可重复 `--config key=value` 配置对照，参数值不写入采集器摘要，但不得传入秘密。`--approval-policy on-request` 可观测审批请求；采集器固定自动拒绝，并与真实人工介入分开计数。

`summary.json` 保存实际线程/轮次、工具/审批/交接/压缩事件、usage 和 trace 摘要；`collected` 只表示采集完成。调用者提供的归档摘要不证明安装字节，配置模型不冒充请求级模型认证；未获得的 session、人工介入或审批标识保持未知。评分者须查阅 trace、验证安装与用户旅程，再按上节合同登记结果。采集器不生成发布通过声明；fake backend 测试仅验证协议与存储行为。

## 指标

黑盒智能体运行至少跟踪：

- 调用精确率/召回率；
- 入口路由准确率；
- 安全恢复与完成准确率；
- 过期证据和冲突检测率；
- 重复/返工率；
- 人类介入和错误批准请求；
- token、工具调用、耗时、重试和成本；
- 实现后的文档漂移。

在相同案例上比较“使用/不使用技能”和不同发布候选。只有质量与安全门仍通过时，成本更低或轮次更少才算改进。确定性合同结果不应伪造不存在的 token、成本或人工介入指标。

## 验收

当确定性套件通过、结果输入绑定有效、既有通过案例没有无理由退化、新行为有代表性案例，且风险所需的独立前向审查者无需隐藏上下文即可遵循本技能时，变更才可交付。Codex 黑盒 harness 不可用时必须标记 `unable_to_verify` 并阻止上线；不能用确定性套件代替或降级成笼统说明。

源码发布门与提取后的 `--installed` 自检边界见[发布与恢复·已安装工件自检](发布与恢复.md#已安装工件自检)。合成 schema fixture 独立存于 `tests/fixtures/`，不得从真实发布记录推导成通过证据。

## 推进旅程观察

`evals/progress_cases.json` 固定八类隔离旅程：完整实施、仅规划后续接、新鲜检查点续接、陈旧帧协调、审查失败后的修复、插入问题/约束、调查分支回收与窄包交付；另以补充边界案例观察用户明确撤销原实施目标后的范围调整，保留原应用字节且只交付新目标文档，不把状态文本匹配当语义通过。通过 `scripts/run_progress_evals.py` 复用实际 App Server 采集器，不新增状态协议或宿主自动调度。

夹具和提示的操作语言必须符合实际运行时合同。若错误写集或初始范围漂移造成额外往返，归为采集条件缺陷并保留混杂说明，不能算作技能操作负担；修正后以新输入重新采集，旧样本保持原身份。

采集命令的 `--out` 必须是新建私有目录，`--results` 必须是未存在的文件；只运行一个旅程可加 `--case`。多进程只使用不同的目录和结果文件；合并者先核对冻结输入一致，再保留全部样本，不并发写同一记录。

```text
python3 scripts/run_progress_evals.py --collect --candidate /absolute/source --out /absolute/private-new --results /absolute/new-result.json --retention-until 2026-11-09T00:00:00Z --timeout 180
python3 scripts/run_progress_evals.py --results evals/progress_results.json
python3 scripts/run_progress_evals.py --results evals/progress_results.json --verify-private
```

上述日期仅是输入示例，实际采集选择尚未到期的绝对期限。默认 verify 只核对已保存来源及结果结构；private 校验还核对受控原始文件，仍不自动认证评审身份、解释行为或建立收益。改变采集输入需要新样本，不能仅改旧输入摘要获得当前通过。

结果分开保存原始采集身份与 source/fixture/目标绑定、实际应用检查、以及必要独立语义核验。脚本不能从 collector completed 推导验收成功；合成夹具的批准或 critic actor 只用于状态合同，不能充当真实独立审查或用户授权。审查修复场景的最终修复产物需要另行独立复验。失败、超时及未知样本保持原始记录，后续成功版本单独绑定，不重绑旧失败。

统计只描述所观察事件。命令形式的资料读取和状态调用属于候选归因，子进程、截短命令与隐式读取可能不可观测；不能把执行源码脚本算作全文读取。首个应用产物必须能回到实际事件或产物观察，无法定位时为 null。无依据重复验证、错误询问、选择是否合理需独立语义判断，不能用相同命令重复出现自动认定错误。累计用量不能与完整成本或上下文窗口占用等同。

单候选、单次代表性采集可诊断行为，不能证明操作错误下降、加载量减少或推进更快。收益需要同目标、同验收、同能力与版本清楚的对照；未满足时继续记录 unknown，不以新增工具数、测试数或文档数判收益。完整发布与收益资格仍分别由既有宿主门决定。原始输运仅在受控外部目录保留，绝对期限、访问控制和脱敏遵循本协议。
