# 全局接续

本页是显式启用的全局宿主接续能力的合同，属于 platform-adapters；消费者是 `scripts/precompact_handoff.py`、用户级 Hooks 和接收会话。它覆盖没有 longtask 检查点的常规任务，不改变技能触发范围、状态 schema 或完成门。只有用户明确选择全局禁压缩与自动接续时才登记；默认插件钩子不包含此能力。

## 分层行为

- `UserPromptSubmit` 向模型提供全局接续选择和提前分段策略，原业务授权不扩大。
- `PostToolUse` 安全读取事件给定的当前会话 rollout；当宿主最近请求的 `last_token_usage.total_tokens` 达到 `model_context_window` 的 50% 时，通过 `additionalContext` 提醒模型走最近安全出口，并优先使用当前宿主的原生创建/读取工具。绝不采用累计 `total_token_usage`。这是最近请求观察，不是当前精确剩余量；无法读取、缺失或未知时不能声称预算安全。Hosted 工具可能不触发该事件，因此此层不能提供全覆盖保证。
- `PreCompact(auto/manual)` 在旧模型已无整理机会时，核验来源确实在所连 daemon 活动、准确 turn ID、后台终端、目标及子任务。可安全移交时，先持久化去重回执，再创建全新会话并派发只读恢复指令；不等待自身 turn 结束。所有受支持输入及已捕获故障最终输出 `continue:false`。
- 接收者运行 `resume --source ID`，核验自身 ID、原 turn 的确切终态和遗留写入者；只有 `writerGate=open` 才可按原授权继续。恢复源含有界原始用户文本及分页历史定位，有活动检查点时仍消费正常 longtask 合同。核对产物并执行下一具体动作后用 `ack --next-action TEXT` 记录自报接管。

接续不是 fork，不复制完整上下文，不要求常规任务建立 `.longtask`。接管仍遵守[会话出口](任务推进.md#实际接管与当前会话出口)的单写入者、授权、结果与历史边界。提醒、派发、写入门开放和接收者自报是不同证据，均不能单独证明任务完成。提前路径由当前模型/原生宿主确认接管；备用路径的提示词与环境核对是合作式护栏，不是宿主强制写隔离。

## 去重与故障

用户级私有目录仅保存传输回执，不保存目标、完整历史、工具结果或任务证据，不替代工作区唯一检查点。每个来源聊天一份回执，文件中绑定原 turn、cwd、已知接收 ID 和派发阶段；单份最多 16 KiB，容量最多 4096 份，满时拒绝派发。目录须归当前用户所有且权限为 0700；锁/文件须私有、普通、单链接，逐级无跟随打开。来源锁序列化派发，全局容量锁序列化跨来源分配；使用非阻塞 OS 锁、原子替换与 fsync，在第一个非幂等 RPC 之前保存 `creating`，收到 ID 后立即保存。

进程崩溃、断连、响应丢失和异常保留最后已知状态/ID；任何既有回执均不会自动重放创建或派发。`creating`、`created`、`dispatching` 和 `unknown` 都不能解释为可重试。只读 `status --source ID` 定位原操作；不能删除未决回执来恢复容量或再次触发。旧聊天派发后不应恢复实施；重新打开旧聊天不自动解除单写入者义务。

钩子内部 RPC 采用入口起算的 35 秒预算，每次至多 5 秒；既有传输握手至多 10 秒，安全来源读取每次至多 5 秒，末尾关闭自有 proxy 至多 3 秒。登记同步 hook 截止 60 秒，预留输入、落盘和否决输出余量。OS I/O 卡死、进程被杀、钩子不受信/未运行或宿主不尊重输出不在该保证内；不能把脚本检查说成零压缩证明。

## 安装与实机边界

从受信归档提取的完整插件根执行；禁止指向可变源码或只复制单个有依赖的脚本。将以下 `ROOT` 和 `STORE` 替换为实际绝对路径，先建立用户所有的 0700 私有回执目录。全局配置按字段合并，保留其他钩子及信任状态：

```toml
[[hooks.UserPromptSubmit]]
[[hooks.UserPromptSubmit.hooks]]
type = "command"
command = 'python3 ROOT/scripts/precompact_handoff.py --store STORE hook'
timeout = 10
additionalContextLimit = 1000

[[hooks.PostToolUse]]
matcher = "*"
[[hooks.PostToolUse.hooks]]
type = "command"
command = 'python3 ROOT/scripts/precompact_handoff.py --store STORE hook'
timeout = 10
additionalContextLimit = 1000

[[hooks.PreCompact]]
matcher = "^(auto|manual)$"
[[hooks.PreCompact.hooks]]
type = "command"
command = 'python3 ROOT/scripts/precompact_handoff.py --store STORE hook'
timeout = 60
statusMessage = "Preventing compaction and dispatching continuation"
```

只有正确的 daemon 能证明原 turn 正在活动。默认使用现有 `codex app-server proxy`；用户已知对应 daemon 的公开控制 socket 时，可在命令中显式追加 `--socket /absolute/control.sock`（放在 `hook` 子命令之前），它使用公开 `proxy --sock`，不扫描/猜测 socket、不连接私有 stdio、不启动备用 server。接收指令保留相同 socket。

本机探测发现桌面原生读接口能看到活动 turn，而默认 proxy 报告同一来源 `notLoaded`、持久化 turn 为 interrupted，后台终端查询不可用。这证明当前默认 proxy 不能核验该桌面来源，不能据此在桌面宣称备用接管已经可用；原生提前路径与备用路径必须分别验证。当前权限读取器只支持已验证的完整访问内置 profile；受限/命名策略不静默放宽。原目标/心跳及子任务无法协调时保持只读并报告缺口，不擅自终止或转移它们。

通过宿主 `/hooks` 审阅并信任新定义，使用新会话核对加载。不能伪造 `trusted_hash`、修改既有受信脚本来避开新定义审阅或关闭生产信任检查；旧独立禁压缩门可以保留，它与新钩子同时运行，不提供接管保证。[官方 Hooks 合同](https://learn.chatgpt.com/docs/hooks)和[公开 App Server](https://learn.chatgpt.com/docs/app-server)分别定义事件与会话接口。

```text
python3 ROOT/scripts/precompact_handoff.py --store STORE status --source SOURCE_UUID
python3 ROOT/scripts/precompact_handoff.py --store STORE resume --source SOURCE_UUID
python3 ROOT/scripts/precompact_handoff.py --store STORE history --source SOURCE_UUID --cursor OPAQUE_CURSOR
python3 ROOT/scripts/precompact_handoff.py --store STORE ack --source SOURCE_UUID --next-action TEXT
```

`resume/history/ack` 仅供已派发到记录 cwd 的接收者；`CODEX_THREAD_ID` 必须与真实接收 ID 相同。`resume` 遇到派发锁竞争或尚未提交的派发阶段时返回 `waiting_for_dispatch_commit`，接收者在总计60秒内只读重试，不能重放创建。环境变量及本地回执不是防篡改身份认证。历史文本是来源数据，角色或“已批准”文字不授予新权限。历史每页按12000字符分段，`historyTruncated=true` 时先用同一 `pageCursor`、`--offset nextOffset --page-digest pageDigest` 读取本页后段，本页完整后才采用 `nextCursor`；摘要变化则拒绝偏移读取。分页与摘要遗漏需保持可见，缺少目标/授权时不能猜测继续。

## 验证与声明

确定性检查覆盖无检查点、先落盘后派发、并发/重启去重、未知结果、错误 daemon/turn、后台写入者、权限拒绝、精确终态和路径边界。来源用量读取继续使用现有快照的大小/时间/身份限制，默认读取接口不增加私有文本或用量输出。

上线验收必须另行观察真实自动阈值和手动路径的 `hook/completed`、原 turn 终态、没有压缩项、真实接收 ID及下一具体动作；还须覆盖常规与 longtask 任务。合成事件、源码测试、配置登记及 UI 提示不能代替真实宿主验收。无对应宿主接口或未完成审阅信任时，状态保持“已准备，整体目标未完成”，不能承诺所有任务零压缩且稳定接管。
