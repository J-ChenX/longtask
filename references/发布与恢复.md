# Codex 当前版本发布与恢复

本文是 longtask 3.0.0 发布、安装和故障恢复的权威合同。3.0.0 仅供个人 Codex 宿主使用。

## 发布闭包

```bash
python3 scripts/build_release.py build --root . --output dist/longtask-3.0.0.zip
python3 scripts/build_release.py verify --root . --archive dist/longtask-3.0.0.zip
```

`release-manifest.json` 定义唯一发布闭包；其中排除 `evals/host_results.json`、`evals/invocation_results.json` 和 `evals/forward_results.json` 等易变执行记录；随包保留案例、协议与测试。重新记录时间或耗时不会改变发布字节；修改任何随包指令、合同或代码仍会改变摘要并要求匹配的新证据。其中不得包含 `.claude`、`.claude-plugin`、历史归档、`.longtask/` 临时检查点或 `docs/tasks/` 旧任务记录。构建和验证都必须失败关闭，并限制文件数、单文件大小、总大小、链接和路径类型。任何子目录无法枚举都终止构建及源码验证；验证/提取会非阻塞打开归档并拒绝 FIFO 等非普通文件。

脱离源码工作区验证或提取时，必须携带由受信渠道取得的非空 SHA-256：

```bash
python3 scripts/build_release.py verify \
  --archive dist/longtask-3.0.0.zip \
  --expected-sha256 '<trusted-sha256>'

python3 scripts/build_release.py extract \
  --archive dist/longtask-3.0.0.zip \
  --destination '<empty-staging-directory>' \
  --expected-sha256 '<trusted-sha256>'
```

## 个人 Codex 安装

安装前检查 `~/.codex/skills/longtask`；若存在旧的独立技能副本，先备份到技能发现目录之外，避免它与 3.0.0 插件产生同名入口。此操作只清除发现冲突，不迁移或读取旧状态。

将校验并提取出的完整目录原子放到 `~/plugins/longtask`。默认个人市场位于 `~/.agents/plugins/marketplace.json`：文件不存在时可直接采用 [`personal-marketplace.json`](personal-marketplace.json)；已存在时只合并其中的 `longtask` 条目并保留其他条目。该条目的本地源必须保持为 `./plugins/longtask`，不要为默认个人市场执行 `codex plugin marketplace add`。

```bash
codex plugin add longtask@personal
```

随后启动全新 Codex 任务，确认六个入口均从同一插件发现。更新或同版本恢复时，先验证新归档并原子替换整个 `~/plugins/longtask`，再执行 `codex plugin remove longtask@personal` 和上述安装命令以清除旧缓存；不得复制零散技能或直接安装可变工作区。

## 单宿主发布门

发布证据只覆盖个人 Codex CLI。核心场景、重复采样、适用性与证据要求以[评测协议·黑盒智能体执行评测](评测协议.md#黑盒智能体执行评测)为唯一权威。必须验证当前受信归档的真实行为、授权边界和恢复；个人发布不把未认证的宿主标识冒充高保证身份。

`release_gate` 判断核心发布资格；`benchmark_gate` 判断能否声称成本或性能收益。完整对照缺失只阻止后者，关键行为或恢复缺失仍阻止前者。静态合法的部分完成记录可以保留已通过的宿主层；命令 `--require-release-pass` 列出具体剩余条件。

## 当前版本恢复门

3.0.0 不做跨版本回滚。恢复演练必须绑定同一当前归档，并验证：

1. 受信摘要验证通过；
2. 工作区状态和用户项目先完成独立备份；
3. 在空暂存目录完成干净安装；
4. 模拟失败安装后能清理未完成暂存物且不破坏现有安装；
5. 从同一 3.0.0 受信归档完整重装；
6. 全新 Codex 会话能重新发现技能并完成代表性恢复流程。

恢复汇总状态必须由全部机械子检查推导；通过时必须携带当前归档摘要及 run/trace 关联。恢复不是状态降级，也不得把旧状态写入 3.0.0 schema。

## 兼容性策略

- 1.x/2.x 插件布局、状态和证据不受支持；3.0.0 运行时直接拒绝。
- 不提供迁移命令、兼容读取分支、降级写入或跨版本回滚。
- 历史工作区仅可在隔离副本中用对应历史工具只读取证，不得由 3.0.0 继承批准、完成或恢复授权。
- 新工作必须初始化新的 3.0.0 状态；同版本修复只替换完整受信工件。

最终发布检查：

```bash
python3 scripts/validate_longtask.py --require-release-pass
```

## 已安装工件自检

在从受信归档提取的插件根执行 `python3 scripts/validate_longtask.py --installed`。该模式验证嵌入逐文件清单、安装闭包和随包合同，不要求未随包分发的宿主、调用和前向运行结果；它与 `--require-release-pass` 互斥，不能证明上线通过。默认源码校验和正式发布门仍要求源码侧三类评测结果。单元测试使用独立的合成 fixture，提取后也可运行。
