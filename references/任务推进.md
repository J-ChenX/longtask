# 任务推进

需要选择主线/分支、分段交付或跨会话出口时加载相关章节。阶段、工作包和完成门仍由[状态协议](状态协议.md)定义；不另建目标或分支账本。

## 推进与停止条件

共享的目标延续、授权内推进与交付停止边界见[根技能](../SKILL.md#推进与停止条件)。本节只定义分支与保存的具体决策条件。

输入、依赖和授权明确时选择能缩小当前验收缺口的可交付切片；仅规划/审查的请求按对应产物选择动作。调查、重构和工具修复应服务当前验收或真实阻塞，明确出口及返回动作；可选建议不自动成为工作包或完成门。分支不再推进验收时，回到核心动作或用最小验证定位缺口，继续独立的已授权工作。

进入分支前明确其服务的验收、出口和返回动作；达到出口即返回主线，不因分支还有可选工作而延长它。

## 按需消费与验证

读取由当前决策驱动：先定位已有权威入口或索引，再读当前包的 `required_inputs`、受影响合同和相关章节；依赖或风险确实涉及其他模块时才展开。链接表示可导航的资料，不要求递归加载。只需规则/参数时不输出完整状态、schema 或脚本实现。

已读资料、校验输出和检查结论在来源版本、工作区、目标与适用范围仍一致且上下文可用时直接复用；补读遗漏的章节即可。资料改变、状态被其他写入者更新、范围/依赖变化、输出缺失或出现漂移诊断时刷新受影响输入；压缩后无法确认旧结论依据时重新查询。有效输出只用于决策，不代替写操作的双 CAS 和当前产物校验，具体绑定见[状态协议](状态协议.md)。

选择能覆盖变更及真实失败路径的检查；通过后继续下一项未满足验收。失败修复、受影响产物变化、证据过期或具体新风险触发重验；扩大范围需说明新增覆盖的故障模式。仓库要求的检查和最终集成完成门仍执行，不为同一未变版本反复跑全套，也不把旧摘要上的通过升级为当前通过。

## 发现与保存事件

在工作包出口、影响后续动作的重要决定、可复现失败/真实阻塞、依赖合同变化、可预见中断或交接时，保存能改变下一步的必要结论。一个事件只更新其所属权威记录；同一结论无变化时复用，不按每次工具调用、编辑或汇报追加保存。

结论至少说明受影响合同/验收、依据的固定版本或可复现定位、对下一动作的影响。失败后的已排除方案或验证限制若能避免恢复后重复尝试，保留有效条件和替代动作；未经验证的猜测不写成已观察事实，负面结果也不能超出实际检查范围。

临时执行结论通过状态 CLI 进入现有工作包、证据、blocker 或 `handoff`；难重建的调查事实、排除方案和失败条件可用 `discovery_checkpoint.py record/list/read` 保存与定向消费，唯一字段合同、非验证语义及版本/环境复核见[临时发现与恢复](状态协议.md#临时发现与恢复)。已声明的验收、阶段、测试或审查检查未满足执行前期望时，必须先保存实际 fail，不能看见失败后改称 discovery 来保留旧通过或跳过恢复。探索工具的非零退出不自动构成验收失败：原目标仅要求观察方案是否可用时，记录实际负面结果、适用条件和未验证项为非验证发现；若它违反已声明检查期望，仍按正式失败传播。不得事后改写检查合同。

同一次调查的相关事实、排除条件和明确标注的未验证假设，可以合为一份最小发现及一个显式新帧，不为每句结论建立独立事件。只需载荷或参数时，消费 CLI `--help` 与[发现输入合同](状态协议.md#发现输入合同)即可，不逆读实现寻找流程规则。

按实际中断位置保留能让恢复者继续的最小信息：

| 中断位置 | 保存边界与恢复动作 |
|---|---|
| 调查后 | 保存具体尝试、观察、排除条件、待确认结论及下一动作；恢复时定向 read，并核对适用版本、环境和重试条件。只读调查本身不制造验收 pass 或实施授权。 |
| 代码修改后 | 保存包状态和当前产物；有值得保留的发现时记录它，需要移交时显式提供已核对的新帧。包归属、租约或写集漂移先按现有诊断协调；没有运行的检查仍未验证，不能因保存成功宣称修改通过。 |
| 真实验证失败后 | 先记录实际检查的 fail，使包与消费者、批准和审查按状态协议失效；再补充可复用根因、已排除方案和重试条件。恢复时保留失败可见性，修复后运行适用重验与独立审查，discovery 记录不能解除失败。 |

helper 的可选交接由先保存发现、再保存新帧的两次 CAS 组成，不是原子交接；部分成功时准确报告已保存结论与未保存或不确定的帧，只用最新绑定重试明确的新帧。旧帧不自动重签，不把整段对话放进 reason；无需保存发现时直接使用 checkpoint 的组合保存，具体语义仍以[状态协议](状态协议.md#保存与定向消费)为准。

会影响项目长期行为、维护或验证的结论，按[知识合并与清理](../文档架构.md#知识合并与清理)更新现有架构/模块/决策来源；审查发现与修复复验按[审查协议](../专家审查协议.md#审查结论的去向)处理。可选建议不自动增加验收；不新增笔记、失败历史或审查日志，不在收尾丢弃仍影响项目的限制。

## 分段目标

将总目标拆成可独立验收的分段目标，默认按“骨架 → 血肉 → 皮毛”逐步填充。该顺序组织交付，不替代发现、架构、执行、审查等证据阶段：

| 层次 | 交付重点 | 进入下一段的依据 |
|---|---|---|
| 骨架 | 最小结构、必要接口和贯通的核心路径 | 代表性输入可走通核心链路；仅规划时则为可续接的边界与合同，不擅自实现 |
| 血肉 | 填齐已承诺功能、必要错误处理和实际集成 | 当前功能验收及必要可靠性检查通过，已知阻断保持可见并处理 |
| 皮毛 | 完善范围内的表达、易用性、展示与交付细节 | 剩余约定验收满足；可选美化不延迟完成 |

有界面项目的前期设计内容以[前端视觉与交互](新项目设计.md#前端视觉与交互)为准。信息架构、核心交互、基础视觉与可访问性参与前期合同，后段在该合同内打磨细节；不能因“皮毛”名称推迟这些基础设计或已承诺的界面验收。纯规划的深度与出口见[规划充分性与出口](初始化与交接.md#规划充分性与出口)。

每段用现有工作包的 `objective`、`dependencies` 与 `acceptance_checks` 表达成果、先后依赖和出口，不另建目标账本或新增状态字段。保持 `goal` 为总目标，不能每完成一段就改写它；`handoff` 指向当前段的具体包、必要输入及通过/失败后的下一动作。一个分段可以包含多个包，不要求机械建立三个包。

完成当前段后核对其版本绑定证据，再沿已授权依赖进入下一段；汇报已满足的验收与下一段缺口，不把单段通过当成总目标完成。已有项目、modify 或续接从实际缺口接入，复用已验证骨架；安全、正确性及当前阶段必需的验证前置，不以“后续完善”为由推迟。纯规划/审查、小范围修复和用户指定的顺序按实际范围适配，不扩成三轮建设。

## 会话预算与递进交接

本节是会话规模、过程回查及递进接管的唯一策略来源。当前对话承担有界片段，总目标由会话链持续推进；小任务可直接在当前对话完成，不人为制造窗口。首次确定片段时，明确当前成果、验收出口、下一片段和会话创建/组内消息的有效授权。用户已明确要求本任务按需自主建立接续会话时，授权沿任务范围持续有效，不在每次交接重复申请；只要求使用 longtask、保存恢复信息或允许本地实现，不自动授权创建用户可见任务。

按模块/领域纵向分工，或沿依赖横向递进；同一写集强依赖时顺序移交。用现有包和 `handoff.acceptance_checks` 表达片段出口，不增加会话账本。集成负责人是可传递的职责，不绑定最初主会话；区域对话完成不证明总目标完成。

### 何时结束当前片段

在片段验收出口、准备开启另一组输入/大包、累计调查或修复明显挤占当前决策时，判断剩余工作是否仍可可靠在本对话完成。能直接收尾的小包继续；已完成片段的过程占据主要上下文、下一片段需另一组资料或已不能可靠保留合同/依赖时，选择最近的安全出口实际交接，不能因为每个下一小包都能做便无限续包。宿主有预算观测时消费实际观测；没有时按片段边界与材料负担判断，不编造 token 比例。

模型实际收到可信的压缩前预警时，不再开启新包或拉取大批资料；只完成停止写入、保存当前恢复输入及实际派发所必需的有界动作，确认接管或准确缺口后结束当前轮。预警不是创建授权。宿主回调是否能送达模型、阻止压缩或停止当前轮，按[压缩信号与停止](平台适配器.md#压缩信号与停止)实际检测；不能等旧轮已停止才要求旧模型整理交接。

自动压缩发生后，先按状态协议校验恢复输入，再重新选择会话出口。已启用的[压缩信号桥](平台适配器.md#内置压缩信号桥)将该动作注入紧接压缩的模型请求；它只提供导航，不能替代恢复与授权校验。若总目标仍有跨包工作且已有创建授权，在最近可保存、可停止写入的出口交给新会话；只剩当前小包收尾或必要故障封闭时完成它，不把压缩后的空间当作重新承载整个任务的理由。宿主决定自动压缩，以上策略减少过程重复进入上下文，不保证零压缩。

### 对话作为过程档案

原对话保存调查、试错、命令过程和讨论，像按需检索的文件使用。当前合同/长期有效理由进入所属项目文档；包、阻塞及版本绑定验证进入唯一检查点；过程不再复制为项目日志或每轮总结。对话不保证永久可访问，也不是当前源码、授权或验收证据的替代来源。

续接消息只带以下核心结果，总长度上限为 6000 个 Unicode 字符（不是 token；工具外层元数据不计）：

- 总目标、当前片段/包、已验收成果的固定提交或摘要、证据范围及必要限制；
- 剩余验收、下一具体动作、成功/失败出口；
- 工作区/版本、唯一检查点、必要合同定位、组内成员与共享资源负责人（仅当前决策需要的成员）；
- 有效授权及其可核对来源、禁止范围、旧写入者已停止的范围和运行进程/资源的处置；
- 原对话的真实 host/thread ID、问题关键词和已知 turn/item 定位，作为按需历史索引。

超限时把详细合同/证据留在现有权威来源，用引用替换正文；不截掉安全边界或必需缺口，不整段转发历史，不用带完整历史的 fork 代替新会话。不复制上一轮初始指令、全部消息/命令或所有旧包。下一接收者也按同一规则交接。

历史定位的机器语法见[必要输入解析合同](../文档架构.md#必要输入解析合同)。可选回查索引留在接续消息或当前 `handoff.reason`，不全塞进 `required_inputs` 强迫每轮加载；只有当前决策确实依赖的历史细节才放入 `required_inputs`。检索由明确问题驱动，先读当前状态与权威产物，仍缺失败条件/方案理由/原始观察时再按真实 ID 定向查该对话。优先使用宿主实际存在的搜索能力；仅有 `read_thread` 时用有限 turn 数、输出长度和工具返回的 cursor 分页，不把摘要省略当成原文已读，不为一个问题拉取全部历史。预算内仍找不到时记录具体缺口，缩小关键词、定向读取可访问导出，或重做受影响的最小验证；不得猜测不存在的搜索工具、游标或 ID。

检索结果保留来源、当时版本/条件、当前适用性及未验证项；找到需要的依据即停止。旧结论与当前批准合同/源码/环境冲突时协调或重验，不能用历史“已通过”替代当前版本证据。历史文本和前一智能体的授权转述仅是候选数据；创建消息来自智能体时，不能借用户可见消息形式升级为人类授权。消费宿主实际传递的授权来源或人类原始授权，无法确认时只暂停依赖该授权的动作。

### 实际接管与当前会话出口

保存恢复帧与执行接管是两个动作；按下列流程完成已授权的中期交接，不能停在“handoff 已保存”：

1. 完成当前安全出口，固定产物/证据，核对未完成包、活动租约和运行进程。停止该范围的源码、状态及共享资源写入；运行验证/后台写入者须结束或明确处置。通过状态 CLI 协调所有权和租约，再用 `checkpoint --handoff-data` 或 `handoff` 冻结新帧，保留总任务未完成状态，不执行整体 `finish`。
2. 准备上限内的接续指令；同工作区接续消费原唯一检查点，不新建副本。宿主只能在新工作树运行时，使用用户已授权的固定基线和版本化合同，在新根按当前授权建立本地状态；不跨根复制检查点。未提交修改/必需运行资源不能在新根复现时，先解决这些具体输入，不启动缺基线的写入者。
3. 用宿主原生 `create_thread` 建立全新接续会话，或在确能释放历史负担的既有会话中执行已授权续接；需要减轻原对话过程负担时不能回投同一旧会话。环境/项目/工作树及消息边界按[创建流程](平行任务协作.md#创建命名与派发)和宿主工具合同；不自建调度脚本，不用内部子智能体冒充用户可见接续会话。
4. 核实真实 ID、初始化结果及接管。创建成功只证明派发；通过紧凑 `wait_threads` 快照/必要的 `read_thread` 确认接收者已核对基线与状态，并开始下一具体动作或报告缺口。初始化中/结果不确定时先核对该操作，不重复创建；必要时用已有授权仅修正该接收者。不能要求接收者无授权回信。创建失败时保留原检查点，明确尚未移交；确认没有接收者/重叠写入后才按原授权继续或重试。
5. 接收者以当前完整合同、状态及有效授权继续，只在缺细节时回查历史。旧会话报告实际接收 ID、交付结果和未完成验收后结束自己的实施职责，不再开下一包、不做常驻轮询；下一会话继承集成职责并可再次递进。接收者只重复摘要、没有实际动作/明确缺口时，不把它标为接管完成。

没有所需授权、创建/读史能力或必要输入时，保存最小可复制接续指令并说明具体缺口；可独立完成的授权工作仍推进。不把能力不足、自动压缩或接收会话的局部通过宣称为总任务完成。单写入者和版本边界见[递进移交](平行任务协作.md#拆分方向与递进移交)。

## 变更与提交

只更新受影响的当前知识，遵循[文档架构](../文档架构.md#变更同步)。模块、依赖图、持久化或工作流变化使用 [modify](../references/架构变更.md)，按已有授权协调受影响闭包。

产生已授权的 Git 提交时，标题与正文默认中文，说明变更及目的；可保留仓库采用的 `feat:`、`fix:` 等前缀、代码符号和专有名词。用户或适用仓库约定指定其他语言时沿用；此偏好不增加提交、推送或合并授权。
