# 任务推进

需要选择主线/分支、分段交付或跨会话出口时加载相关章节。阶段、工作包和完成门仍由[状态协议](状态协议.md)定义；不另建目标或分支账本。

## 推进与停止条件

共享的目标延续、授权内推进与交付停止边界见[根技能](../SKILL.md#推进与停止条件)。本节只定义分支与保存的具体决策条件。

输入、依赖和授权明确时选择能缩小当前验收缺口的可交付切片；仅规划/审查的请求按对应产物选择动作。调查、重构和工具修复应服务当前验收或真实阻塞，明确出口及返回动作；可选建议不自动成为工作包或完成门。分支不再推进验收时，回到核心动作或用最小验证定位缺口，继续独立的已授权工作。

在工作包边界、重要决定、可预见中断或交接时保存可恢复的必要状态。进入分支前明确其服务的验收、出口和返回动作；达到出口即返回主线，不因分支还有可选工作而延长它。

## 分段目标

将总目标拆成可独立验收的分段目标，默认按“骨架 → 血肉 → 皮毛”逐步填充。该顺序组织交付，不替代发现、架构、执行、审查等证据阶段：

| 层次 | 交付重点 | 进入下一段的依据 |
|---|---|---|
| 骨架 | 最小结构、必要接口和贯通的核心路径 | 代表性输入可走通核心链路；仅规划时则为可续接的边界与合同，不擅自实现 |
| 血肉 | 填齐已承诺功能、必要错误处理和实际集成 | 当前功能验收及必要可靠性检查通过，已知阻断保持可见并处理 |
| 皮毛 | 完善范围内的表达、易用性、展示与交付细节 | 剩余约定验收满足；可选美化不延迟完成 |

每段用现有工作包的 `objective`、`dependencies` 与 `acceptance_checks` 表达成果、先后依赖和出口，不另建目标账本或新增状态字段。保持 `goal` 为总目标，不能每完成一段就改写它；`handoff` 指向当前段的具体包、必要输入及通过/失败后的下一动作。一个分段可以包含多个包，不要求机械建立三个包。

完成当前段后核对其版本绑定证据，再沿已授权依赖进入下一段；汇报已满足的验收与下一段缺口，不把单段通过当成总目标完成。已有项目、modify 或续接从实际缺口接入，复用已验证骨架；安全、正确性及当前阶段必需的验证前置，不以“后续完善”为由推迟。纯规划/审查、小范围修复和用户指定的顺序按实际范围适配，不扩成三轮建设。

## 会话预算与递进交接

优先在当前一个对话内完成已授权且规模可控的任务。先推进能形成验收结果的小步骤，按需加载、复用有效结论、缩短反馈，不为规划全部细节、重复历史或旁支讨论消耗上下文；不要为了使用 longtask 人为拉长任务或制造会话。

需要拆分时，除了按模块/领域纵向划分，也可按前后依赖横向划分步骤或时段。让每个片段具有在一个对话内完成的有界成果、验收和下一步；分段目标不必与会话一一对应，不以固定轮次或时间长度代替验收。职责独立且可并行时纵向拆分，强依赖链或同一写集连续完善时优先顺序递进，可按实际范围组合。

当前片段完成后，若剩余验收仍能在现有上下文可靠推进，则继续当前对话；输入规模、剩余步骤或上下文丢失风险已影响可靠性时，在清晰出口主动保存最小 `handoff`，供下一步骤续接。交接只带总目标、已验收成果的固定版本、当前段/包、剩余验收、必要输入和有效授权，不复制整段对话或重做上一步。仅片段完成时保留未完成检查点，不运行总任务 `finish`。

多窗口和顺序写入的交接边界见[拆分方向与递进移交](平行任务协作.md#拆分方向与递进移交)。创建、发消息和暂停会话仍遵循用户授权与宿主工具合同；没有相应能力时交付可复制的交接内容，不假称新会话已启动。自动压缩由宿主决定，技能只能减少触发压力并保留恢复兜底，不承诺禁止压缩。

## 变更与提交

只更新受影响的当前知识，遵循[文档架构](../文档架构.md#变更同步)。模块、依赖图、持久化或工作流变化使用 [modify](../skills/longtask-modify/SKILL.md)，按已有授权协调受影响闭包。

产生已授权的 Git 提交时，标题与正文默认中文，说明变更及目的；可保留仓库采用的 `feat:`、`fix:` 等前缀、代码符号和专有名词。用户或适用仓库约定指定其他语言时沿用；此偏好不增加提交、推送或合并授权。
