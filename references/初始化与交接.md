# 初始化与交接

用于新项目的规划阶段，尤其是“本轮只规划，下次继续”。`{skill-root}` 是插件根，`{workspace-root}` 是项目根。已读取的资料直接复用；本页给出常规参数，不需要为组装命令输出整个 schema 或阅读实现源码。状态不变量仍以[状态协议](状态协议.md)为准，异常时只查相关章节。

## 先建立可恢复入口

确认用户目标、授权范围和空项目身份后，先确保 Git 忽略 `/.longtask/`（无 Git 不需要初始化 Git）。**在编写架构或模块文档之前**执行：

```text
python3 {skill-root}/scripts/planning_checkpoint.py begin --root {workspace-root} --actor planner --goal "用户批准的目标及本轮范围" --next-action "尚未编写架构和工作包；继续规划，暂不实现应用"
```

保留返回的完整 `task_id` 和 `revision`。此时即使后续生成中断，也已有目标和未完成事项。已有检查点不得再次 `begin`；通过 `route --resume-choice inspect` 检查后，使用 `save` 或对应恢复入口。

## 分段规划并保存

按[文档架构](../文档架构.md)先写能支持下一步决策的最小架构，再按需要展开模块合同。每完成一组文档、登记一包或准备进入较长生成步骤时保存，不把全部交接留到最后。

规划内容与项目规模相称：简单双模块工具先明确目标、模块边界、输入输出、依赖和代表性验收即可。保留影响正确性的待定决策；完整测试矩阵、详细实现算法及尚未触发的风险分析在相应工作包执行时展开，不在初始化重复铺写。核对当前规划所需的一次结构检查后就保存并报告交接，避免反复读取完整状态和重复核对。

```text
python3 {skill-root}/scripts/planning_checkpoint.py save --root {workspace-root} --actor planner --expected-task-id {id} --expected-revision {revision} --next-action "已写架构，尚缺统计输出模块合同；继续规划，暂不实现应用"
```

登记工作包时给 `save` 增加 `--package 'JSON'`；可重复使用，按依赖先后排列。以下是可直接替换的最小合同；`base_revision` 可省略，由助手使用当前规划快照，其他字段必须明确填写。不要把示例的风险、回滚或验收照抄成事实。

```json
{
  "id": "reader", "objective": "读取UTF-8文件并按批准口径解析",
  "status": "planned", "dependencies": [],
  "affected_modules": ["读取解析"], "write_set": ["reader.py", "tests/test_reader.py"],
  "acceptance_checks": ["固定输入解析结果符合模块合同"],
  "risk": "仅本地文件读取；编码和空输入边界需验证", "risk_level": "low",
  "required_review_roles": ["quality"],
  "rollback": "实施前建立可恢复的基线；规划中尚无实现改动",
  "stopping_condition": "需求冲突、范围扩大或验收不符时停止",
  "owner": null, "lease_expires": null, "contributors": []
}
```

助手先保存当前文档交接，再逐包调用状态 CLI，**每包成功后立即重新冻结交接**，最后验证状态与交接新鲜度。返回新 `revision` 后继续复用，不能重新从旧值猜测。助手不直接写状态、不自动重试 CAS 冲突、不执行检查点自由文本，也不会批准设计、推进阶段或生成验收通过证据。

多条状态命令不是一个跨命令事务；硬中断仍可能留下过期交接。失败时保留已保存进展，先检查当前状态和已登记包，不能覆盖或重新初始化。仅新增包时可能部分成功，依照输出的已完成操作恢复。

一次保存包含多个包时，中间交接明确标注登记尚未完成，并以当前包列表为准；传入的 `--next-action` 只作为全部成功后的预定下一步。最后一包保存成功后才写入最终交接，避免部分成功却提前声称全部完成。

若发现 `.initializing.json`，按[故障恢复操作](状态协议.md#故障恢复操作)用相同参数重试原始状态 CLI 的 `init`，完成原事务；不要再次运行 `begin` 或删除中断标记。

## 仅规划结束

对照用户目标核查架构、模块合同、依赖和验收项后，再次 `save`，将 `--next-action` 写成具体剩余事项及下一会话的授权边界，例如“架构和两个工作包已形成，实施尚未开始；下次先复核规划并确认实施范围”。该步骤只表示规划交接已保存，不表示应用或整个任务完成，**不执行 `finish`**。

检查输出 `checkpoint_saved=true`、`handoff_stale=false`、`handoff_conflict=false`；然后直接向用户报告产物与断点。不要为让阶段名称看似完整而额外登记未执行的检查、强行推进阶段。计划与证据尚未完成的阶段可以留待下次继续。若确实完成阶段出口检查并需继续推进，使用状态 CLI 登记实际证据与 `transition`，再用 `save` 刷新交接。

助手只处理 `setup` 的 discovery/architecture/documentation 及 planned 包；其他模式或已开始实施的任务使用普通状态 CLI。隔离示例：`python3 {skill-root}/scripts/demo_workflow.py --scenario planning`。示例验证早期检查点、逐步保存和无应用完成声明，不是宿主模型执行证明。
