# Longtask 既有项目接入

说明：“我正在使用 longtask-retrofit 恢复这个已有项目的状态和意图。”

1. 阅读仓库说明，检查清单、源码、测试、Git 历史、已有文档和当前工作树改动。
2. 阅读[主技能](../../SKILL.md)、[文档架构](../../文档架构.md)和[状态协议](../../references/状态协议.md)。
3. 从用户和已有持久来源恢复有边界的初步目标，明确标注不确定性；然后以 `retrofit` 模式初始化 v3 状态，不得把当前代码直接视为已批准意图。
4. 根据内聚性和真实依赖推断模块边界。把当前代码/运行时行为记录为 `observed`，并绑定版本证据。
5. 继续从用户陈述、测试、议题、决策和维护中的文档恢复预期行为。无支持的结论标为 `inferred`，矛盾标为 `disputed`。目标改变时使用状态工具的 `goal` 命令。
6. 按[推进与停止条件](../../SKILL.md#推进与停止条件)限定接入范围，创建导航、合同、恢复和未来决策所需的最小 L0/L1 文档；人读型文件使用职责概括后的中文名称。
7. 识别废弃路径、安全/信任问题、缺失验收证据和开放意图问题。除非另有请求，不要重构代码。
8. 校验状态与文档，然后分别报告已观察、推断、有争议和仍未知的内容。

完成后按[文档架构·知识合并与清理](../../文档架构.md)收敛项目内容并运行 `finish`；不创建任务知识或归档文件。
