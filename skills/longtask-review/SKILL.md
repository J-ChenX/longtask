# Longtask 审查

说明：“我正在使用 longtask-review 进行独立审查。”

1. 阅读仓库说明、[主技能](../../SKILL.md)和[专家审查协议](../../专家审查协议.md)。
2. 存在临时检查点时校验其 v3 状态。存在 `handoff.intent=review` 时，确认其摘要、HEAD 和证据代际新鲜，并以 `target`、`required_inputs` 和 `acceptance_checks` 确定本次被审对象；没有检查点时，可对用户明确指定的当前项目范围执行只读审查并现场冻结摘要；不要为审查制造任务档案。冻结目标不明确时说明限制，不得把“上一步”猜成某个产物或伪造批准证据。
3. 按不同风险选择审查者；获得授权且能力可用时使用独立子智能体。只提供最小上下文，不提供预期结论或先前发现。
4. 运行与各审查者主张相关的确定性检查。
5. 按根因综合结论，保留分歧和覆盖缺口；在当前回复中交付结论；状态更新获授权时只写临时结构化证据，不复制审查日志。
6. 只读审查请求中不得修改代码或文档。失败 review evidence 会生成指向本次 `check_id` 和 finding ID 的 `remediate` 交接；用户要求修复时，保留原始发现、修复版本和独立复验证据，并在新摘要上生成新的 review 交接。
7. 只有全部阻断项关闭且审查摘要等于当前产物摘要时，才能批准审查状态。

授权修复后的正确行为、回归测试和当前限制按[文档架构·知识合并与清理](../../文档架构.md)合并到项目内容，已修复发现不形成长期清单。
