# Longtask 初始化

说明：“我正在使用 longtask-setup 初始化这个项目。”

1. 阅读仓库说明，确认不存在有意义的既有实现；已有代码使用 `longtask-retrofit`。读取[主技能](../../SKILL.md)，已加载的内容不重复读取。
2. 明确用户目标与本轮范围，只有关键缺失信息才询问。随后沿[初始化与交接](../../references/初始化与交接.md)的 `begin` 路径，**先建立任务检查点，再生成架构与模块文档**。不要先输出完整 schema、所有命令帮助或实现源码来研究常规用法。
3. 按[文档架构](../../文档架构.md)逐步形成最小架构和可验证工作包，区分 approved 与 inferred。每完成一组文档或登记工作包，沿同一操作路径 `save`，把已完成部分、剩余事项和当前授权边界写入新鲜交接。
4. 用户只授权规划时，对照目标检查计划后再 `save` 并报告交接；保留 planned 包和未完成检查点，不实施应用、不伪造验收或推进阶段、不运行 `finish`。较长生成前也应先保存当前未完成进展。
5. 用户已授权整体实施时，无需再询问“是否开始”；按主技能的[推进与停止条件](../../SKILL.md#推进与停止条件)推进实际阶段、证据和工作包；后续意图变化使用状态工具协调，不覆盖旧任务。

状态字段、CAS 与恢复的权威要求见[状态协议](../../references/状态协议.md)，按当前操作加载相关章节。助手只保存规划，不替代批准或完成合同；其他阶段仍使用主技能的执行、审查与清理流程。
