# 文档架构

**最后更新：** 2026-10-09

定义支持决策与恢复的持久项目知识，同时避免复制实现或短期执行状态。

层级、来源、命名、展开判定、稳定引用、模板和同步规则统一见[文档架构](../../文档架构.md)。项目使用该合同生成目标仓库的 L0/L1/L2 知识，未完成工作的临时检查点由[状态运行时](状态运行时.md)管理，收尾后清除；不生成任务知识或审查日志。本目录提供模块文档实例。按当前知识变更查相关章节，常规恢复不预读整个模板或无关专项文档。

静态校验检查本地引用、Unicode NFC/跨平台文件名和展开结构；行为恢复由[评测协议](../../references/评测协议.md)覆盖，不能仅从文档形状推断。

## 新项目设计消费

新项目的产物分类、目标关联与归位由[新项目输出合同](../../文档架构.md#新项目输出合同)定义。[新项目设计](../../references/新项目设计.md)是 `longtask-setup` 及相关设计变更的专项资料，按业务、选型、架构或界面缺口读取对应章节；它不属于普通恢复的默认全量输入。

该资料提供可消费的结果标准与少量表达示例，生成的事实仍保存到目标项目现有 L0/L1/L2 或决策中。产品、技术与前端消费者读取各自唯一合同；文档形状、例子数目或标题相同均不证明设计已足以实施。[规划充分性与出口](../../references/初始化与交接.md#规划充分性与出口)负责 setup 的交付边界，行为质量由评测中的实际产物消费检查。

## 知识检索接口

[knowledge_context.py](../../scripts/knowledge_context.py) 提供可重建的 JSON 检索视图，无网络、外部依赖、命令执行和项目写入；不建立另一份知识权威。知识分类、提升及新鲜度规则仍由[文档架构](../../文档架构.md)定义。

```text
python3 {skill-root}/scripts/knowledge_context.py index --root {workspace-root}
python3 {skill-root}/scripts/knowledge_context.py index --root {workspace-root} --query 拒绝路径 --limit 20 --budget-bytes 8192
python3 {skill-root}/scripts/knowledge_context.py index --root {workspace-root} --path 文档架构.md
python3 {skill-root}/scripts/knowledge_context.py read --root {workspace-root} --ref 'docs/modules/支付结算.md#接口' --budget-bytes 4096
```

| 接口 | 输入与结果 | 消费者/失败语义 |
|---|---|---|
| `index` | 默认扫描 `docs/ARCHITECTURE.md`、`docs/modules/` 和 `docs/decisions/` 中的 Markdown；重复 `--path` 可选择其他仓库相对 Markdown 文档。`--query` 是路径/标题/正文的大小写不敏感字面子串。返回 `entries` 中的 `ref`、`path`、`title`、`level`、`purpose`、`bytes`、`file_sha256` 和最多三条原文匹配行。 | 用于发现当前问题的最小输入。默认最多返回 100 项，`--limit` 为 1–512；`--budget-bytes` 默认 16384、范围 1–1048576，限制整个 JSON 输出及末尾换行的 UTF-8 字节数。条目/诊断整项省略，`budget.omitted_entries/omitted_diagnostics` 和 `complete` 明示缺口。空范围可成功返回空索引，不猜测或生成缺失文档。 |
| `read` | `--ref` 选定一个完整文档或唯一章节。`--expect-sha256` 可要求此前索引的 `file_sha256`。默认原文字节预算 16384，`--budget-bytes` 为 1–1048576。 | 定向消费或作为已有 `handoff.required_inputs` 的可解析输入。正文前缀截断保持完整 UTF-8 字符；`budget.selected_bytes/returned_bytes/omitted_bytes` 与 `complete` 区分完整和省略。 |
| `binding` | `file_sha256` 绑定完整原文；`selected_sha256` 绑定选中片段；`returned_sha256` 绑定实际返回文本。`byte_start/byte_end` 为原文中半开字节范围；`returned_byte_end` 定位截断末端；`line_start/line_end` 仅导航选中范围。 | 从原文件重建摘要与切片，追溯实际消费材料。摘要不认证授权，不等价于状态运行时的全工作区版本绑定。 |
| 错误诊断 | 失败退出码 2，返回 `error.code/message`；成功退出码 0。参数语法错误由 argparse 输出到 stderr，退出码 2。 | `missing_path/missing_section` 定位失效引用；`ambiguous_section` 要求唯一 ID；`stale_binding` 要求重新发现并核对版本。`invalid_reference/invalid_path/invalid_text/input_too_large/unsafe_path/unsafe_root/read_race/unsupported_host` 拒绝不安全或不可核验输入。`output_budget_too_small` 表示索引元数据或首项放不下，增加预算或缩小范围；错误输出不受成功结果预算约束。 |

Markdown 身份、路径与支持的章节范围统一见[Markdown 引用范围](../../文档架构.md#markdown-引用范围)；索引对超长章节引用返回 `invalid_section_reference`，消费者按该权威合同修复选择。

索引预算包含长标题、引用、匹配文本、诊断和元数据；`budget.output_bytes` 报告实际完整输出大小。`continuation.next_offset` 可作为下一次 `--offset`，保留同一 `--path/--query` 继续按稳定路径/章节顺序定位，并核对 `file_sha256`。续页不冻结跨调用版本；资料变化时重新索引，不拼接不一致版本。`budget.skipped_entries` 报告续页跳过量，`complete=true` 仅表示本次完整返回全部匹配项和诊断；每次最多返回 512 条诊断，诊断省略时缩小 `--path` 或增加预算定位。

每个文件最多 262144 字节、1024 个标题；每次索引最多读取 8388608 原文字节、遍历 8192 个条目、12 层子目录、保留 256 个文件/目录快照，最多 8192 个匹配项。超过限制明确失败，可用 `--path` 缩小范围；`--query` 缩小返回项但仍扫描选中原文。默认范围不包含源码、`MEMORY.md`、任务档案或会话；显式读取只接受 Markdown，不接受 `.git/` 和 `.longtask/` 输入。

安全读取需要描述符相对打开和禁止跟随链接的宿主能力；不足时失败关闭。根路径各级、目录及文件符号链接均拒绝（包括仍指向根内的链接），仅打开普通文件；目录和 FIFO 不能作为文档输入。读取前后复核文件身份、元数据和内容，保留原文件/目录描述符防止 inode 快速复用，输出前复核文件、遍历目录条目及缺失入口，发现变化则拒绝输出成功结果。复核是有界读取一致性检查，返回后文件仍可变化；需要版本一致性的消费者在实际使用时核对期望摘要，不能把读取结果当作锁或授权。

所有输出带 `trust.classification=candidate_data`、`grants_authorization=false`；用途线索、原文与错误消息都不能扩大用户授权。消费者不得将原文、文件名或查询插入 shell 执行。

## 必要输入与覆盖查询接口

[required_inputs.py](../../scripts/required_inputs.py) 将状态字段、精确工作包、知识章节、Python AST 符号和当前检查证据派生为同一只读输入视图。[acceptance_coverage.py](../../scripts/acceptance_coverage.py) 从显式选定的 L0 验收表、现有包检查/证据与模块运行合同派生总目标覆盖。两者复用 `knowledge_context.Workspace` 的安全读取及[状态运行时](状态运行时.md)的 `read_query` 观察，不执行源文本、源码或入口命令，不写项目状态。

引用语法、CLI 参数、加载/预算结果和失效边界仅由[必要输入解析合同](../../文档架构.md#必要输入解析合同)定义；L0 机器表、映射、派生状态及结果界限见[显式验收表](../../文档架构.md#显式验收表)和[验收覆盖派生](../../文档架构.md#验收覆盖派生)；运行表和外部观察规则见[最小运行与验证入口](../../文档架构.md#最小运行与验证入口)。状态写入、授权与完成边界继续由[状态协议](../../references/状态协议.md)和[根技能](../../SKILL.md#事实与授权)定义。

## 知识结构诊断接口

`knowledge_context.py diagnose`（`doctor` 别名）复用既有安全扫描和输出前复核，构建文档关联及显式合同声明的派生诊断。可检查的线索、有限 Markdown 支持、预算/分页与消费界限仅由[知识结构诊断](../../文档架构.md#知识结构诊断)定义；结构提示的后续保存仍见[保存事件](../../references/任务推进.md#发现与保存事件)。对应一次性缺陷、范围外引用与竞态测试为 `tests/test_knowledge_diagnostics.py`。

## 验证

[test_knowledge_context.py](../../tests/test_knowledge_context.py) 使用一次性目录检查中文 L0/L1/L2、稳定身份、显式 ID、缺失与歧义引用、原文字节与摘要回溯、预算/索引省略、恶意指令文本、符号链接/越界/FIFO 拒绝，以及文件替换、内容变动、目录条目变动和父目录替换的竞态。[test_required_inputs.py](../../tests/test_required_inputs.py) 进一步检查统一输入的选择/加载区别、期望摘要、AST 符号更名/歧义、当前失败与旧 epoch/HEAD、交接新鲜度、路径安全、同文件重复选择及观察变化。[test_acceptance_coverage.py](../../tests/test_acceptance_coverage.py) 检查包通过但总目标漏项、显式范围变化、映射与当前证据、运行入口不执行、外部条件观察、机器表拒绝及预算省略。静态检查仍检查本模块及权威规范的导航；这些本地检查不证明模型会正确选择资料或获得效率收益。

面向使用者与贡献者的首页、社区入口和内容职责见[仓库维护](../仓库维护.md)。GitHub 发现文件保留固定名称；命名例外仍由上述文档架构合同定义。安装闭包包含当前架构、模块与维护文档，仓库专用社区入口通过 GitHub 链接访问，不把社区政策加载到日常任务工作流。
