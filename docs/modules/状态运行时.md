# 状态运行时

**最后更新：** 2026-10-09

## 职责

提供确定性路由、唯一机器可读临时检查点、版本绑定的结构化交接帧、CAS 变更、内容/Git 版本绑定、逐路径基线与写集归属、提交日志一致性、证据失效、工作包所有权租约、风险审查覆盖和完成校验。它不认证 actor 标签、不提供对工作区写入者的防篡改日志，也不证明外部系统状态。

## 接口

| 命令 | 效果 |
|---|---|
| `route` | 只读决定 setup/retrofit/continue/review/complete/error，返回总目标、交接帧、新鲜度和恢复选择；`--resume-choice` 解析显式选择 |
| `context` | 默认只读最小恢复视图；可选 overview 提供字符/UTF-8 字节预算下的包分页、全量诊断计数与阻断定位，package 读取指定包详情；所有视图复用完整观察 |
| `doctor` | 只读汇总状态、恢复选项的禁用原因、租约、工作包替换及证据缺口，返回结构化候选操作 |
| `init` | 在 `.longtask/` 初始化唯一 v3 检查点；替换时校验旧代际/revision/摘要 CAS，不生成历史目录 |
| `checkpoint` | 绑定当前工作区摘要/Git HEAD；可选 --handoff-data 在同一双 CAS 中绑定新帧；仍阻塞过期包/漂移并使旧证据失效 |
| `handoff` | 原子冻结下一窗口的 intent、稳定目标、最小输入、验收条件和一层结果分支；绑定摘要、HEAD、epoch 与修订 |
| `package` | 在 CAS 保护下添加或替换完整输入合同（不是输出记录），区分首次启动与保留基线的续租/恢复，保护 owner 转移与贡献者历史 |
| `evidence` | 对当前摘要记录带稳定 `check_id` 的通过/失败证据；附加到工作包时绑定一个验收检查 |
| `blocker` | 添加阻塞项，或仅凭当前独立验证证据解决它 |
| `review` | 记录非批准审查状态和阻断项数量 |
| `approve` | 把批准范围和 actor 绑定到当前摘要与不可变 HEAD |
| `modify` | 在原任务中进入 L4 变更，冻结受影响依赖闭包并保留其他包 |
| `goal` | 修改意图、取代下游工作包/证据并退回 discovery |
| `reconcile-events` | 修复日志落后或完整日志领先两种事件提交窗口；拒绝自动截断损坏尾记录 |
| `transition` | 应用经过版本检查的合法阶段/状态变化 |
| `finish` | 当前完成不变量和知识合并证据有效时清除状态与日志，保留空锁以防并发锁身份分裂 |
| `validate` | 检查 schema、DAG、冲突、事件日志、证据、审查角色覆盖和完成不变量 |

## 实现与验证

`save_mutation` 统一承担双 CAS、HEAD 漂移失效与原子状态/事件提交；`latest_current_checks` 按检查 ID 汇总当前证据，供阶段出口和 blocker 关闭共用。`cmd_modify` 处理保留任务的 L4 入口；`cmd_init` 在唯一检查点锁内校验代际替换；`cmd_finish` 负责验证后的临时内容清理，不生成归档；写入进程强制退出后的临时文件由持锁恢复路径安全回收。

`_workspace_snapshot` 在一次有界读取中生成摘要与路径清单，`invalidate_stale_packages` 按执行批次检查变化归属，停止包的冻结指纹允许同伴逐个完成并检测事后篡改，`validate_write_aliases` 检查路径/链接安全。指纹只用于检测，恢复来源由工作包声明。`completion_errors` 检查集成版本、批准 HEAD、必要证据和独立审查覆盖；包级验收下界使直接失败和测试失败都不能复用失败前证据。

具体约束统一见[状态协议](../../references/状态协议.md)。验证由 `tests/test_longtask_state.py` 的状态/故障注入测试和 `tests/test_forward_workflows.py` 的受支持 CLI 用户路径共同提供；包括从各原始模式进入架构变更、HEAD 刷新、检查点替换与收尾清理、并行逐包完成、合法写入后的续租/失败恢复、目标修订与失败证据覆盖场景。

工作包写集的路径语言由[状态协议](../../references/状态协议.md)定义；推进夹具另以 `tests/test_progress_evals.py` 的真实 CLI 场景核验目录子路径归属、范围漂移及证据拒绝，避免将错误夹具的操作成本归给运行时。

所有变更支持 `--output summary`，保留 CAS 与警告而省略历史数组。同摘要验证恢复由 `verification_recovery` 同时约束批准和完成；产品审查发现保持原有新版本关闭门。摘要祖先使用固定目录句柄，嵌套仓库共享原始根与预算。实际用法见[操作示例](../../references/操作示例.md)。

恢复输出中的 `choice_required` 仅说明调用方尚未选择动作；运行时不读取会话授权。消费规则见[安全启动](../../SKILL.md#安全启动)，选择后的新鲜度、可用性和阶段校验保持原合同。

`read_query` 统一获取只读观察，`observe_route` 派生恢复选择，`diagnose_observation` 供三个查询共用；返回前检测状态字节、摘要与 HEAD 变化，不承诺快照隔离。`context` 不读取完整证据历史进入输出，也不替调用方选择并行活动包。输出合同见[最小恢复视图](../../references/状态协议.md#最小恢复视图v300)，故障与无副作用验收见 `tests/test_context_view.py`。


`context_overview` 仅构建只读派生定位视图：预算计量包括实际 CLI JSON 和元数据，先以完整状态形成诊断计数/阻断定位，再按预算省略有明确来源的字段或缩短索引页。指定包查询保留全局诊断与全部活动所有权。任何 overview 都明确不可执行；小预算拒绝不隐藏需进一步取数的风险。分页不提供快照隔离，调用方比较观察绑定。输出字段及消费门统一见[预算视图合同](../../references/状态协议.md#有预算的-overview-与指定包详情)，1/10/100 包、长 Unicode、全局阻断、未加载输入与分页验收见 `tests/test_context_budget.py`。

`cmd_checkpoint` 的可选新帧输入复用 `build_handoff`，与摘要刷新在同一次 `save_mutation` 中发布；旧路径不自动重绑帧。拒绝、任务/revision 双 CAS、产品观察变化、批准/审查失效及进程崩溃的首次发布前/后、事件提交窗口覆盖见 `tests/test_checkpoint_handoff.py`。这只缩短保存后另写 handoff 的往返，不改变 schema、epoch、事件恢复或完成门。


`required_inputs.Session` 复用 `read_query` 获取有效状态和工作区观察，同时以知识读取器固定所选状态/事件与来源文件，返回前再比较观察；`current_evidence` 使用既有全局证据身份、包验收下界和当前结果构造派生输入。[必要输入解析合同](../../文档架构.md#必要输入解析合同)定义统一读取的语法及失败边界，[验收覆盖派生](../../文档架构.md#验收覆盖派生)定义其总目标查询消费者。两者只读取现有字段，不增加状态/授权/完成语义。受影响文件变化、最新失败、旧 epoch/HEAD、包被取代和读取竞态的验证见 `tests/test_required_inputs.py` 与 `tests/test_acceptance_coverage.py`。

外部运行入口所需观察统一由[最小运行与验证入口](../../文档架构.md#最小运行与验证入口)定义，消费现有 evidence.details 数据；产物摘要的保证范围仍见[状态协议](../../references/状态协议.md#产物摘要)。
