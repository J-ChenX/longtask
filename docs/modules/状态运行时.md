# 状态运行时

**最后更新：** 2026-10-22

## 职责

提供确定性路由、唯一机器可读临时检查点、版本绑定的结构化交接帧、CAS 变更、内容/Git 版本绑定、逐路径基线与写集归属、提交日志一致性、证据失效、工作包所有权租约、风险审查覆盖和完成校验。它不认证 actor 标签、不提供对工作区写入者的防篡改日志，也不证明外部系统状态。

## 接口

| 命令 | 效果 |
|---|---|
| `route` | 只读决定 setup/retrofit/continue/review/complete/error，返回总目标、交接帧、新鲜度和恢复选择；`--resume-choice` 解析显式选择 |
| `context` | 默认只读最小恢复视图；可选 overview 提供字符/UTF-8 字节预算下的包分页、全量诊断计数与阻断定位，package 读取指定包详情；所有视图复用完整观察 |
| `doctor` | 只读汇总状态、恢复选项的禁用原因、租约、工作包替换及证据缺口，返回结构化候选操作 |
| `init` | 在 `.longtask/` 初始化唯一 v3 检查点；替换时校验旧代际/revision/摘要 CAS，不生成历史目录 |
| `checkpoint` | 绑定当前工作区摘要/Git HEAD；可选 --handoff-data 在同一双 CAS 中绑定新帧；仍阻塞过期包/漂移并使旧证据失效 |
| `handoff` | 原子冻结下一窗口的 intent、稳定目标、最小输入、验收条件和一层结果分支；绑定摘要、HEAD、epoch 与修订；实际宿主接管见[结构化交接帧](../../references/状态协议.md#结构化交接帧) |
| `package` | 在 CAS 保护下添加或替换完整输入合同（不是输出记录），区分首次启动与保留基线的续租/恢复，保护 owner 转移与贡献者历史 |
| `evidence` | 对当前摘要记录带稳定 `check_id` 的通过/失败证据；附加到工作包时绑定一个验收检查 |
| `blocker` | 添加阻塞项，或仅凭当前独立验证证据解决它 |
| `review` | 记录非批准审查状态和阻断项数量 |
| `approve` | 把批准范围和 actor 绑定到当前摘要与不可变 HEAD |
| `modify` | 在原任务中进入 L4 变更，冻结受影响依赖闭包并保留其他包 |
| `goal` | 修改意图、取代下游工作包/证据并退回 discovery |
| `reconcile-events` | 修复日志落后或完整日志领先两种事件提交窗口；拒绝自动截断损坏尾记录 |
| `transition` | 应用经过版本检查的合法阶段/状态变化 |
| `finish` | 当前完成不变量和知识合并证据有效时清除状态与日志，保留空锁以防并发锁身份分裂 |
| `validate` | 检查 schema、DAG、冲突、事件日志、证据、审查角色覆盖和完成不变量 |

## 实现与验证

初始化写入当前技能版本；`skill_version_supported` 统一检查同一大版本，查询和变更保留检查点创建版本，替换任务时仍对兼容状态核验当前产物漂移。兼容策略及证据约束见[当前版本边界](../../references/状态协议.md#当前版本边界)；同大版本查询/变更/完成、格式拒绝、替换漂移和压缩桥消费由状态及 hooks 测试覆盖。

`save_mutation` 统一承担双 CAS、HEAD 漂移失效与原子状态/事件提交；`latest_current_checks` 按检查 ID 汇总当前证据，供阶段出口和 blocker 关闭共用。`cmd_modify` 处理保留任务的 L4 入口；`cmd_init` 在唯一检查点锁内校验代际替换；`cmd_finish` 负责验证后的临时内容清理，不生成归档；写入进程强制退出后的临时文件由持锁恢复路径安全回收。

### Windows 原生文件层

兼容适配设计保留 CLI、v3 状态及同大版本恢复合同。`scripts/windows_fs.py` 是状态运行时和发布工具共用的内部 Windows 后端；不在全局替换 `os`，不承担任务调度或解释器安装。消费者须显式选择后端，把目录遍历、枚举、相对打开、替换、删除和目录刷新一并接入，不能仅替换最初的目录打开。现有 POSIX 路径维持原有安全原语。

后端将原生目录句柄包装为 CRT descriptor，从本地盘根逐分量调用 `NtCreateFile(RootDirectory=固定父句柄)`，仅接受单个规范名称，设置 `FILE_OPEN_REPARSE_POINT` 后检查打开对象的属性，拒绝重解析点。打开盘根后以该句柄的 volume GUID 最终路径核验其确为本地卷根，拒绝把 SUBST 目录别名或网络映射当作安全根；不先查询映射再按易变盘符打开。目录句柄不共享删除权限，阻止被替换及锁身份分裂；普通文件使用二进制 CRT I/O，打开后交还写入 descriptor 前重新核验单链接，截断不能先于该核验。同 POSIX 合作式边界，这不阻止同用户在成功打开后另建硬链接，不提供文件句柄整个存续期的防篡改隔离。

状态目录边界在 Windows 通过固定目录句柄逐级核验，不用 `resolve()` 与原字符串不同判定链接：原生解析也会展开合法的 DOS 8.3 祖先名。允许这种工作区路径拼写不放宽包内 DOS 写集别名拒绝、越界或重解析点限制。私有恢复文件仍须属于当前用户，DACL 精确匹配受保护的当前用户与 SYSTEM 完整控制策略；比较前两侧均经原生 SDDL 序列化，兼容内置 Administrator/System 数字 SID 的 `LA`/`SY` 表示，不接受继承、额外 ACE、较弱权限或不同所有者。

工作区叶子观察使用单独的 `artifact_stat`，不放宽 runtime 与发布的严格 `stat`：只允许 `IO_REPARSE_TAG_SYMLINK`，以同一无跟随叶子句柄读取 `FSCTL_GET_REPARSE_POINT`，把相对标志与 substitute name 纳入身份，再核对读取期间元数据；不打开目标。目录符号链接也只贡献身份，junction 和其他重解析 tag 仍拒绝。原生表示不承诺与 POSIX 相同摘要；证据仍绑定当前主机观察。无 Git 的回退枚举同样使用固定父句柄，不通过 `Path.rglob` 遍历链接目录。

相对重命名和删除由已打开对象的 `NtSetInformationFile` 执行，目标目录仍为固定句柄，不重新拼接解析绝对路径。发布消费者须以 `O_DELETE` 创建可重命名的暂存目录 descriptor，再用 `rename_open` 在同一源句柄上发布；不能保持禁止共享删除的源句柄又按名称重新请求 DELETE 权限。平台适用边界见[原生文件系统能力](../../references/平台适配器.md#原生文件系统能力)。

状态文件写入仍先刷新临时文件，再在固定父目录原子替换并刷新目录。Windows 目录刷新以同一目录句柄的空相对名重新取得可写句柄后执行 `FlushFileBuffers`，不静默吞掉不支持或拒绝访问的错误。`0600`/`0700` 创建使用受保护 DACL，显式 owner 为当前用户、允许当前用户和 SYSTEM 完全控制；崩溃遗留临时文件回收以 owner 和该 DACL 判断私有性，不能套用 POSIX 模式位或仅凭文件名删除。OS 字节锁必须在普通单链接及身份验证后取得，进程退出由 OS 释放。

`longtask_state.py` 显式选择后端，贯通摘要祖先、快照、runtime 枚举/恢复及目录刷新。`runtime_read` 固定父目录并校验单链接、打开对象身份、读前后大小/时间与当前叶子身份；状态、事件和初始化/清理标记不再通过普通路径重开读取。Windows 原子写入以 `O_DELETE` 保留同一暂存文件 descriptor 并直接 `rename_open` 发布；事件保持 UTF-8/LF，锁的兼容字节在成功取得字节锁后才写入。finish 使用后端重命名/删除，保持原锁文件身份。

活动写集的 Windows 观察另以固定目录句柄逐级打开祖先和成员，不使用 `Path.resolve` 或 `os.walk`。严格 `stat` 拒绝 junction 及所有重解析点，读句柄前后核对类型、身份、链接数、大小和时间；目录同时复核成员列表。缺失的未来目标仍可声明，大小写父子别名冲突及后续变更归属同步按分量比较；固定对象句柄的规范最终分量必须与输入名称大小写等价，DOS 8.3 等备用拼写直接以 alias 诊断拒绝，包含仅声明未来叶子的祖先。链接错误沿用 alias/escape 诊断；escape 分类只读取符号链接自身的 substitute name，不打开外部目标。这是合作式变化检测，不是跨全部目标的快照隔离。

知识/必要输入消费者显式选择同一后端，复用固定祖先、流式目录枚举和返回前复核；`iterdir` 允许在节点预算触发时停止原生枚举，不先收集整个目录。固定句柄核对规范分量，拒绝借 DOS 备用拼写绕过 `.git`/`.longtask` 等命名空间限制。普通文档、源码与状态输入拒绝多硬链接，链接数纳入指纹，读取期间新增别名也会使观察失效。`knowledge_context`、`required_inputs` 及其验收覆盖查询消费者在原生 Windows 输出 UTF-8/LF；引用、预算、候选数据及加载合同仍见[知识接口](文档架构.md#知识检索接口)。

`tests/test_windows_state.py` 原生覆盖摘要与链接身份、活动写集的 junction/符号链接/硬链接/大小写别名及检查到打开竞态、runtime 读写、init/context/checkpoint 与过期 CAS、同大版本恢复、锁竞争/分裂及进程退出、强退暂存回收、事件提交的两个崩溃窗口与损坏拒绝，并复用状态合同夹具验证 finish 清理中断后的重新校验。`tests/test_windows_inputs.py` 覆盖原生索引/章节/源码/状态/验收消费者、预算、链接和读取/输出窗口；`tests/test_windows_hooks.py` 使用明确解释器验证桥的原生只读定位、诊断和编码。脚本通过不证明宿主正确解析 hook 命令或已经信任、加载定义；不能用定向通过推断整包 Windows 兼容。

发布消费者 `build_release.py` 显式选择同一后端，已接入源目录枚举、归档读取、目的目录创建与暂存发布、递归失败清理；内嵌清单命名、可移植路径冲突与固定发布模式的权威合同见[发布闭包](../../references/发布与恢复.md#发布闭包)。`tests/test_release.py` 覆盖通用归档边界，`tests/test_windows_release.py` 在原生 Windows 上覆盖 junction、硬链接、二进制受信往返和失败清理。发布消费者通过不能代替状态消费者验收。

`tests/test_windows_fs.py` 在真实 Windows 上覆盖二进制读取、句柄替换/不覆盖、Unicode/多页枚举、私有 ACL、预存及打开窗口新增硬链接拒绝写入、junction 不遍历/不删除、SUBST 隐藏祖先拒绝、单独深层句柄固定祖先、暂存句柄直接发布与文件锁释放；非 Windows 上明确跳过。该后端的单独通过不证明状态运行时、归档、hooks 或安装已兼容。消费者集成验收必须另外覆盖 init/context/checkpoint、过期 CAS、同大版本恢复、竞争写入、崩溃临时文件/事件提交窗口，以及受信归档提取、双构建和 installed 自检。

API 依据为 Microsoft 的 [NtCreateFile](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile)、[NtSetInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntsetinformationfile) 和 [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)；实际可用性仍由目标文件系统测试确定。

公开状态 CLI 和规划入口保留用户根路径的词法分量，再由文件后端逐级固定；不得在安全打开前 `resolve()` 消除链接或 junction 祖先。规划/发现辅助入口按 UTF-8 解码状态子进程输出，并在原生 Windows 自身输出 UTF-8/LF。发布暂存清理仅处理独占创建成功且当前身份仍匹配的对象；暂存名碰撞或观察到身份替换时保留他人对象并失败关闭。

符号链接数据布局依据 Microsoft 的 [Symbolic Link Reparse Data Buffer](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/b41f1cbf-10df-4a47-98d4-1c52a833d913)；display-only print name 不参与目标身份解释。

`_workspace_snapshot` 在一次有界读取中生成摘要与路径清单，`invalidate_stale_packages` 按执行批次检查变化归属，停止包的冻结指纹允许同伴逐个完成并检测事后篡改，`validate_write_aliases` 检查路径/链接安全。指纹只用于检测，恢复来源由工作包声明。`completion_errors` 检查集成版本、批准 HEAD、必要证据和独立审查覆盖；包级验收下界使直接失败和测试失败都不能复用失败前证据。

具体约束统一见[状态协议](../../references/状态协议.md)。验证由 `tests/test_longtask_state.py` 的状态/故障注入测试和 `tests/test_forward_workflows.py` 的受支持 CLI 用户路径共同提供；包括从各原始模式进入架构变更、HEAD 刷新、检查点替换与收尾清理、并行逐包完成、合法写入后的续租/失败恢复、目标修订与失败证据覆盖场景。

工作包写集的路径语言由[状态协议](../../references/状态协议.md)定义；推进夹具另以 `tests/test_progress_evals.py` 的真实 CLI 场景核验目录子路径归属、范围漂移及证据拒绝，避免将错误夹具的操作成本归给运行时。

所有变更支持 `--output summary`，保留 CAS 与警告而省略历史数组。同摘要验证恢复由 `verification_recovery` 同时约束批准和完成；产品审查发现保持原有新版本关闭门。摘要祖先使用固定目录句柄，嵌套仓库共享原始根与预算。实际用法见[操作示例](../../references/操作示例.md)。

恢复输出中的 `choice_required` 仅说明调用方尚未选择动作；运行时不读取会话授权。消费规则见[安全启动](../../SKILL.md#安全启动)，选择后的新鲜度、可用性和阶段校验保持原合同。

`read_query` 统一获取只读观察，`observe_route` 派生恢复选择，`diagnose_observation` 供三个查询共用；返回前检测状态字节、摘要与 HEAD 变化，不承诺快照隔离。`context` 不读取完整证据历史进入输出，也不替调用方选择并行活动包。输出合同见[最小恢复视图](../../references/状态协议.md#最小恢复视图v300)，故障与无副作用验收见 `tests/test_context_view.py`。


`context_overview` 仅构建只读派生定位视图：预算计量包括实际 CLI JSON 和元数据，先以完整状态形成诊断计数/阻断定位，再按预算省略有明确来源的字段或缩短索引页。指定包查询保留全局诊断与全部活动所有权。任何 overview 都明确不可执行；小预算拒绝不隐藏需进一步取数的风险。分页不提供快照隔离，调用方比较观察绑定。输出字段及消费门统一见[预算视图合同](../../references/状态协议.md#有预算的-overview-与指定包详情)，1/10/100 包、长 Unicode、全局阻断、未加载输入与分页验收见 `tests/test_context_budget.py`。

`cmd_checkpoint` 的可选新帧输入复用 `build_handoff`，与摘要刷新在同一次 `save_mutation` 中发布；旧路径不自动重绑帧。拒绝、任务/revision 双 CAS、产品观察变化、批准/审查失效及进程崩溃的首次发布前/后、事件提交窗口覆盖见 `tests/test_checkpoint_handoff.py`。这只缩短保存后另写 handoff 的往返，不改变 schema、epoch、事件恢复或完成门。


`required_inputs.Session` 复用 `read_query` 获取有效状态和工作区观察，同时以知识读取器固定所选状态/事件与来源文件；`InputWorkspace` 对内部检查点采用独立大小策略，知识/源码读取与总输出仍受原预算约束，返回前再比较观察；`current_evidence` 使用既有全局证据身份、包验收下界和当前结果构造派生输入。[必要输入解析合同](../../文档架构.md#必要输入解析合同)定义统一读取的语法及失败边界，[验收覆盖派生](../../文档架构.md#验收覆盖派生)定义其总目标查询消费者。两者只读取现有字段，不增加状态/授权/完成语义。受影响文件变化、最新失败、旧 epoch/HEAD、包被取代和读取竞态的验证见 `tests/test_required_inputs.py` 与 `tests/test_acceptance_coverage.py`。

外部运行入口所需观察统一由[最小运行与验证入口](../../文档架构.md#最小运行与验证入口)定义，消费现有 evidence.details 数据；产物摘要的保证范围仍见[状态协议](../../references/状态协议.md#产物摘要)。

[压缩信号桥](../../references/平台适配器.md#内置压缩信号桥)复用状态运行时的路径与结构校验，只输出定位元数据，不执行版本新鲜度判断，不增加 schema 字段、检查点写入或额外账本。模型恢复仍使用公开 context CLI。

仅依赖失败传播形成的未执行消费者可按[基线协调例外](../../references/状态协议.md#工作包-dag)选择当前执行前摘要；运行时核对自身没有执行/验收/漂移记录，不能凭调用方清除标志取得例外。`tests/test_longtask_state.py` 覆盖真实失败→上游修复与验收→首次启动消费者，以及依赖未满足时的拒绝。
